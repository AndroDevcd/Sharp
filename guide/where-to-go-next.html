Where to go next

  • The README shows what sets Sharp apart: dependency injection in the language, mocks the compiler writes, the GUI toolkit and coroutines.
  • examples has sample programs; examples/gui goes from a to-do list to a full task manager, and to a 3D game.
  • tests/suite/cases has one small, commented program per language feature and library - the quickest way to see how something is written.
  • tools/clion-plugin is an editor plugin for CLion and IntelliJ IDEA.
  • build-scripts/README.md explains how to build Sharp itself, run its tests and make a release.

If the compiler misbehaves

sharpc --unoptimized file.sharp -o name

uses a second copy of the same compiler that was built without the optimizer. If that one works where the normal one does not, you have found a bug worth reporting.
