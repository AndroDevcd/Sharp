    class label

    base widget : behavior, shows_words · source

    label - text on the screen. Made with text(...).

    text("Hello")
text("Total: " + total.value).size(24).color(theme_green)
text(long_paragraph, modifier().max_width(400))     // wraps onto several lines

    .size(px) the font size in pixels (default: the theme's text size) .color(c) the text colour (default: the theme's text colour) .dim() the theme's quieter text colour (captions, hints) .bold() bold .max_lines(n) at most n lines; text cut off ends in "..." .align(how) where the lines sit when the label is wider than its text: ALIGN_START (left), ALIGN_CENTER, ALIGN_END

    Text breaks at a line feed ("\n") always, and between words when it would not fit the width on offer - so a label inside a narrow column wraps by itself. (Compose: Text. Android: TextView. HTML: a span or p.)

    HOW WRAPPING WORKS: measure() is told the room there is. Each paragraph (the text between line feeds) that is wider than the room is cut greedily: words are added to the line while they fit, then a new line starts. The lines are kept for paint(). Measuring text is not free, so the result is remembered for the width it was made for.

    class picture

    base widget : behavior · source

    picture - an image on the screen: from a file, or from a link. Made with image(...).

    image("assets/logo.png")                              // a file, at its own size
image("assets/photo.jpg", modifier().size(120, 80))   // in a box of a size
image("https://example.com/cat.jpg", modifier().size(120, 120))    // from the web

    HOW IT SITS IN ITS BOX

    .fit(FIT_CROP)          fill the box and cut off what does not fit - a photo in a card
.fit(FIT_INSIDE)        show all of it, as large as fits - a logo
.fit(FIT_STRETCH)       pull it to the box's shape (how a picture starts)
.opacity(120)           see-through: 0 .. 255

    WHAT IT LOOKS LIKE is the modifier's business, as for every widget - and all of it works on a picture:

    image("face.jpg", modifier().size(96, 96).clip(shape.circle())).fit(FIT_CROP)      // a round portrait
modifier().corner(12)  .rotate(8)  .scale(1.2)  .blur(4)  .border(2, colour)  .shadow(8)  .opacity(0.6)

    FROM A LINK (http:// or https://). The picture is fetched on a background thread; the window never waits for it. Meanwhile, and if it cannot be had:

    .placeholder("assets/loading.png")      shown until the picture is there (without one: nothing)
.on_error("assets/broken.png")          shown when it cannot be fetched or read
.fade_in(0.2)                           it comes in over a fifth of a second, not at a blow
    image("https://example.com/cat.jpg", modifier().size(160, 120).corner(10))
        .fit(FIT_CROP).placeholder("assets/loading.png").on_error("assets/broken.png").fade_in(0.2);

    A link is fetched ONCE. The file is kept in a cache folder and read from there from then on - also the next time the program runs, and by every picture that shows the same link (a hundred rows of a list fetch it once). gui.image_cache("folder") says where that folder is; unsaid, it is a folder of its own in the system's place for caches. One picture can be kept somewhere else than the rest:

    image("https://example.com/map.png").cache("maps")      // this one goes to the folder "maps"

    A file is loaded the first time the picture is measured and shared from then on (the native side keeps one copy per file). PNG transparency is kept.

    IN A UI TEST without a window no picture is read and no link is fetched: a picture counts as 100 x 100 unless the modifier gives it a size, and one from a link stays as it is while loading (its placeholder).

    (Android: Glide / Picasso / Coil - load(url).placeholder().error().centerCrop(). Compose: AsyncImage. HTML: img with object-fit.)

    class progress_bar

    base widget : behavior, has_value · source

    progress_bar - how far along something is. Made with gui.progress(...).

    gui.progress(done.value / total)            // a fraction: 0 = nothing, 1 = finished

    class remote_pictures

    source

    THE PICTURES FROM LINKS: each link is fetched once, into the cache folder, and every picture that shows it reads that file. FRAMEWORK USE: a program writes image("https://...") and, if it wants, gui.image_cache("folder").

    class rich_label

    base widget : behavior · source

    rich_label - shows a rich_text. Made with text(rich { ... }).

    HOW IT WORKS: every part is cut into WORDS (each with the spaces after it). While measuring, the words are laid out left to right and wrapped to the width; each word remembers its line and how far across it is. Painting then only draws each word where it was put.

    class rich_text

    source

    RICH TEXT - one piece of text with parts that look different: a bold word, a coloured number, a quiet aside.

    text(rich {
    plain("Due ");
    bold("tomorrow");
    plain(" at ");
    colored("9:30", gui.current_theme().primary);
    quiet("  (in 14 hours)");
});

    rich { } runs the block and gathers what plain / bold / colored / quiet said into one rich_text; text(...) shows it. The parts flow like one text: the line breaks between words wherever the width runs out, whichever part the word belongs to.

    plain, bold, colored and quiet only mean something inside rich { } - anywhere else they stop the program with a message that says so. (Compose: buildAnnotatedString with SpanStyle. Android: SpannableString.)
