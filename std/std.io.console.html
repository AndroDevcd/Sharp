    class ansi

    source

    ANSI escape sequences: the control codes terminals understand for colours, bold / underline, clearing the screen and moving the cursor.

    println(ansi.colored("error:", ansi.red) + " file not found");
println(ansi.styled("Title", ansi.bold));
print(ansi.clear_screen());

    Every function only builds a string; nothing is printed here (see the class console for printing). A sequence is the escape character (code 27), '[', numbers separated by ';', and a letter - e.g. "\e[31m" switches to red and "\e[0m" back to normal.

    Colours are numbers: the constants below (black .. white) and their bright variants (bright_black .. bright_white). Linux and macOS terminals and the Windows Terminal understand these codes; the old Windows console prints them as garbage. When output goes to a file or another program, call ansi.set_enabled(false) once: then every function returns its text without any codes (and the cursor / clear functions return "").

    Everything is static.

    class console

    source

    Talking to the person at the terminal: printing numbers the short way, coloured output, clearing the screen, and asking for input with validation.

    console.print_line("Total: " + io_strings.number_to_string(7.5));
console.print_colored("warning", ansi.yellow);
name := console.prompt("Your name: ");
age := console.read_int("Your age: ");            // asks again until it is a whole number
level := console.read_int_between("Level (1-5): ", 1, 5);
if(console.confirm("Continue?")) { ... }

    This class adds to the plain functions print(), println() and read_line() of std/console.sharp; it does not replace them. Everything is static.

    The end of the input (the input was a file or a pipe and it is used up, or the user pressed Ctrl-D) is noticed: read_line_or_null() returns null, and the functions that have to return something throw io_exception instead of waiting or asking for ever. (The plain read_line() does not notice it.)

    static def prompt(message: string) : string

    Print message (without a line end) and read the line the user types. Throws io_exception when the input has ended.

    static def prompt_or(message: string, fallback: string) : string

    Like prompt(), but an empty answer (just the enter key) gives fallback. The message should say what the default is. Throws io_exception when the input has ended.

    static def read_int(message: string) : decimal

    Ask for a whole number: print message, read a line, and ask again (after a short note) until the answer is a whole number such as 42 or -7. Spaces around the number are ignored. Throws io_exception when the input has ended.

    static def read_int_between(message: string, low: decimal, high: decimal) : decimal

    Ask for a whole number from low to high (both allowed); asks again until the answer is one. Throws io_exception when the input has ended and illegal_argument_exception when low is greater than high.

    static def read_line_or_null() : string?

    Read one line typed by the user, without the line end. Returns null when the input has ended before a single character could be read. A "\r\n" line end (windows, or a file made there) is taken as one.

    static def read_number(message: string) : decimal

    Ask for a number, with or without fraction (3, -0.5, 1e6); asks again until the answer is one. Spaces around the number are ignored. Throws io_exception when the input has ended.

    def key_waiting() : bool

    IS A KEY WAITING TO BE READ? - without waiting for one.

    read_char() waits until a key is pressed, which stops everything else the program does. A program that has to keep going - a game's loop, a machine's control loop - asks first:

    if(key_waiting()) {
    key := read_raw_char();         // comes back at once: the key is already there
}

    (C: kbhit(). Java has no such thing: System.in.available() is the nearest.) It is false when the input is not a console at all (a file, a pipe that has ended).

    def print(data: _int8[])

    PRINTING. print() writes its value, println() the value and a line end.

    What is printed goes into a buffer of the runtime and reaches the screen (or the file, or the program that reads it) a few milliseconds later, in large pieces - at once when the program waits for input or ends. Nothing here flushes, and a program does not have to: flush() is for the rare case that the output must be out before the very next instruction.

    A text is handed to the runtime whole (print_bytes), a line end with it: println("...") is one step, however long the line.
