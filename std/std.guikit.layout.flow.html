    class column

    base widget : behavior · source

    column - children stacked top to bottom.

    column(modifier().padding(16)) {
    text("Title").size(24);
    text("some words underneath");
    button("OK") { save(); };
}.gap(12)

    .gap(n) room between the children .align(how) how children sit ACROSS the column: ALIGN_START (left, the default), ALIGN_CENTER, ALIGN_END (right), ALIGN_STRETCH .justify(how) where the children go when the column is taller than they need: JUSTIFY_START (top, the default), JUSTIFY_CENTER, JUSTIFY_END, JUSTIFY_BETWEEN .center() both in the middle

    A child takes leftover height with modifier().grow(1) or .fill_height(); a spacer (gui.spacer()) is the usual way to push things apart. All the placing is done by the shared algorithm in flex.sharp; a column is that algorithm going DOWN. (Compose: Column. CSS: flex-direction: column. Android: a vertical LinearLayout.)

    class flex

    source

    flex - the ONE algorithm behind both gui.row() and gui.column().

    A row and a column are the same thing turned 90 degrees, so the layout is written once in terms of two directions:

    MAIN  direction: the way children follow each other (down, in a column)
CROSS direction: the other one                      (across, in a column)

    and sideways (1 for a row) says which is which. The small functions at the bottom (main_of, cross_of, measure_kid) read "the main size" of a view without the algorithm caring whether that is its width or its height.

    MEASURE decides every size, in this order (the order Compose's Row/Column uses - RowColumnMeasurePolicy - and for the same reasons):

    1. Children WITHOUT a share are measured first, each offered the room the ones before it left. Measuring these first is what keeps a child with a share from eating the room of a fixed child that comes after it (a growing text before a button must not squeeze the button out). 2. The room that is left is split among the children WITH a share (.grow(n), or filling along the main direction), in proportion. Each is measured ONCE, told its exact main size - so a text that wraps works out its height for the width it really gets. The split is done on running totals, so the rounding of one child is made up by the next and the shares add up to the room exactly. 3. The container is as big across as its biggest child. 4. With ALIGN_STRETCH, children are then measured once more, told to be exactly that big across.

    When the main direction is unlimited (a column inside a scroller), there is no "leftover room" to share: a share is ignored and the child is simply its natural size.

    ARRANGE only decides positions: where the run of children starts and how much extra room goes between them (justify), and where each child sits across (align).

    (CSS flexbox with flex-grow, Android's LinearLayout with layout_weight: the same idea. LinearLayout measures weighted children twice; telling them their exact size up front, as here, needs only one measure each.)

    class spacer

    base widget : behavior · source

    spacer - empty room.

    gui.row().add(title).add(gui.spacer()).add(close_button)     // pushes them apart
gui.column().add(a).add(gui.gap(24)).add(b)                  // exactly 24 pixels between

    gui.spacer() takes all the leftover room of the row or column it is in (it is a child with grow(1) and nothing to paint). gui.gap(n) is a fixed amount of room. (Compose: Spacer. CSS: a flex: 1 div.)

    class wrap

    base widget : behavior · source

    wrap - children side by side like words in a paragraph: when the line is full, the next child starts a new line.

    wrap {
    for(i : _int64 = 0; i < tags.size(); i++) { tag_chip(tags.at(i)); }
}.gap(8)

    Unlike a grid, the children keep their OWN widths - a short tag takes little room, a long one more - so it is the layout for tags, chips, a toolbar that should fold onto a second line in a narrow window.

    .gap(n) room between children on a line, and between lines

    Each line is as tall as its tallest child, and shorter children sit in the middle of the line. (Android: FlexboxLayout with flexWrap. Compose: FlowRow. CSS: flex-wrap: wrap.)

    HOW IT WORKS: one walk over the children, keeping a pen position. A child that does not fit on the current line (and is not the first on it) moves the pen to the start of the next line. measure() does the walk to learn how tall the whole thing is; arrange() does the same walk again to place the children - the same code (flow), so the two can never disagree.
