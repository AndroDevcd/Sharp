    class model_store

    source

    model_store - the models of one screen (or of the app). FRAMEWORK USE: apps ask for models with model_of<...>().

    current is the store a model asked for right now goes into. A screen makes it its own while its content is built, and every composable remembers which store was current when it was made - so a part of a screen that is built again later, on its own, still finds the models of ITS screen (composable.sharp).

    class saved_store

    source

    SAVED STATE - values that are still there the next time the program runs.

    theme_choice := saved("theme", 0);          // a whole number
text_size    := saved("text_size", 16.0);   // a decimal number
user_name    := saved("user_name", "");     // text

    saved(key, first) gives an ordinary state: read it and set it like any other, and screens follow it. The difference is that every change is written to a small file, and the next run starts with what was written instead of with first.

    A whole list, with two functions that turn an item into text and back:

    tasks := saved_list<task>("tasks",
            { t: task -> return t.to_text(); },
            { s: string -> return task.from_text(s); });

    (Android: DataStore / SharedPreferences. Compose: rememberSaveable is the same idea for the length of one run.)

    WHERE THE FILES ARE

    One plain text file per key, named after the key, in the app's data folder:

    Linux       ~/.local/share/<app>/        (or $XDG_DATA_HOME/<app>/)
Windows     %APPDATA%\<app>\

    <app> is the window title given to gui.run, in small letters with anything that is not a letter or digit turned into "_" ("Sharp GUI - tasks" -> "sharp_gui_tasks"). gui.data_name("tasks") sets another name; call it before gui.run.

    The files are plain text on purpose: you can read them, edit them, and delete one to reset a setting.

    WHEN THE VALUE IS READ

    A saved state is usually a field of the app's root composable, and that object is made BEFORE gui.run(...) is called - before the app's name is known. So a saved state made early simply waits: gui.run opens the store, and every waiting state then takes its value from its file, before the first screen is built. One made later reads its file at once.

    class view_model

    source

    view_model - the LOGIC of a screen, kept apart from what the screen looks like.

    class tasks_model base view_model {
    tasks := state_list<task>();            // what the screen shows
    busy  := state(0);
        def add(title: string) { tasks.add(task(title)); }      // what the screen can ask for
    def remove(t: task)    { tasks.remove(t); }
}
    class tasks_screen base composable {
    model := model_of<tasks_model>();
        override def build() : element {
        return column {
            for(i : _int64 = 0; i < model.tasks.size(); i++) { task_row(model.tasks.at(i)); }
            button("Add") { model.add("New task"); };
        };
    }
}

    THE RULE: the screen is dumb. It READS the model's states and CALLS the model's functions - it decides nothing. The model knows nothing about widgets: no text(...), no modifier, no colours. Then the logic can be read, changed and tested without a window, and the screen can be redesigned without touching the logic. (Android / Compose: ViewModel, with StateFlow for the states.)

    HOW LONG A MODEL LIVES

    model_of<tasks_model>() gives the screen's model: made the first time it is asked for, and THE SAME ONE every time after - a screen is built again and again, and its composable objects are made anew, but the model stays.

    The model belongs to the SCREEN it was asked for in (a screen of a navigator: screens.sharp). Every composable of that screen that asks for the same class gets the same model, so parts of a screen share one. When the screen is popped off its back stack the model is dropped and its cleared() runs. A tab's first screen is never popped, so its model lives as long as the app.

    Outside any screen (an app without a navigator) the model belongs to the app and lives until the window closes.

    SLOW WORK

    A model must not make the screen wait. Reading a file, asking a server, crunching numbers: start it with launch(...) on a background dispatcher, and bring the result back with on_main:

    def load() {
    busy.value = 1;
    launch(dispatchers.io()) {
        found := task_store.read_all();     // on an IO thread: the window stays alive
        on_main {
            tasks.replace_all(found);       // back on the main thread: the screen follows
            busy.value = 0;
        };
    };
}

    Work started with the model's launch is CANCELLED when the model is dropped, and the model's on_main does nothing once the model is gone - so a screen that was closed while it was loading cannot be written to by the answer that arrives late. (Android: viewModelScope.launch.)

    WITHOUT A WINDOW

    A model is plain logic, so it also works in a console program or a test: make it with new, call its functions, read its states. Two things differ and are worth knowing: nobody drops it (call drop() yourself to run its when_cleared blocks), and nobody runs what on_main handed over - call main_queue.run_waiting() where you want it run. model_of<...>() itself is for screens: called with no window ever opening it still hands out a model, but that model is never dropped.

    A model class must be makeable with no arguments: model_of makes it. What a model needs from outside it takes from the route (give it a function like open(id) that the screen calls once) or from an object the app shares.

    Fields

    alive_int641 from when the model was made until it is dropped: work that comes back late checks it

    Functions

    def drop()

    Drop the model by hand: its work is cancelled and its when_cleared blocks run. The framework does this for a model made with model_of; call it yourself only for one you made with new (a console program, a test).

    def launch(where: coroutine_dispatcher, block: ()()) : job

    Start block on the threads of where (dispatchers.io() for anything that waits, dispatchers.default_pool() for computing) and return at once. The work belongs to the model: it is cancelled when the model is dropped. To change a state from inside it, use on_main.

    def on_main(action: ()())

    Run action on the main thread - the one place where states may be changed. Does nothing if the model has been dropped by the time the main thread gets to it.

    def when_cleared(action: ()())

    Run action when the model is dropped (its screen was popped, or the app closed): stop what it started, save what must be kept. Say it in the model's constructor:

    tasks_model() {
    when_cleared { connection.close(); };
}

    (Android: ViewModel.onCleared. It is a function you hand over rather than one you override, so a model with nothing to clean up writes nothing at all.)
