    class channel<t>

    : send_channel<t>, receive_channel<t> · source

    channel<t> - a queue between coroutines: send() on one side, receive() on the other, and whoever is too fast is suspended until the other side has caught up.

    USAGE numbers := new channel<int>(16); // see channels for the capacities

    launch(numbers, { s: object ->                   // the producer (state object: THE CLOSURE RULE)
    out := s as channel<int>;
    for(i : decimal = 0; i < 100; i++) { out.send(i); }
    out.close();
});
    total : decimal = 0;
for( ;; ) {                                      // the consumer
    n := numbers.receive_or_null();
    if(n == null) { break; }                     // closed and empty
    total += n!!.value;
}
// or: numbers.for_each({ n: int -> ... });

    Any number of coroutines may send and receive on the same channel; every element is received exactly once. Elements of one sender arrive in the order they were sent. Waiting senders and receivers are served first come first served. It works the same from plain fibers and threads (there the waits simply cannot be cancelled).

    CLOSING close() "nothing more will be sent". Elements that are in the channel, including those of senders that are still waiting, can be received; after that receive() throws closed_channel_exception and receive_or_null() returns null. send() throws at once. cancel() close() from the consumer side: also throws away what is in the channel and makes waiting senders fail.

    t must be an object type (channel<int>, not channel<decimal>).

    Kotlin equivalent: kotlinx.coroutines.channels.Channel<E>. Java equivalent: java.util.concurrent.BlockingQueue (SynchronousQueue, ArrayBlockingQueue, LinkedBlockingQueue for the first three capacities). Go equivalent: chan T.

    LOCKING DISCIPLINE lk (a stripe of lock_stripes, picked once) guards buffer, senders, receivers, closed and cancelled, and is the guard of every waiter queued here. No other lock is taken while it is held, nothing that can throw and no user code runs inside a lock block; waiters are unparked and exceptions thrown after the lock is released. A waiting sender carries its element in waiter.item; a waiting receiver is handed its element through waiter.item.

    Suspends: send (full), receive / receive_or_null / for_each / to_list (empty). All of them are cancellation points. try_send, try_receive, close, cancel and the queries never suspend.

    override def cancel()

    The consumer gives up: closes the channel, throws away the elements that are waiting in it and makes senders that are waiting fail with closed_channel_exception. Never suspends. Kotlin: ReceiveChannel.cancel()

    override def close()

    No more elements will be sent. Receivers that are waiting on the empty channel wake up (closed_channel_exception / null); elements that are still in the channel stay receivable. Closing twice is harmless. Never suspends. Kotlin: SendChannel.close()

    override def for_each(action: (t)())

    Call action(element) for every element until the channel is closed and empty. The way to "iterate over a channel".

    The action runs in-line in the calling fiber (it may capture locals). SUSPENDS while it waits for the next element; a cancellation point. An exception of the action ends the loop and is thrown on; the channel is left as it is. Do not call for_each from inside the action of another for_each on the same fiber (THE NESTING RULE, std/io/coroutines/scope/scopes.sharp); use a receive_or_null() loop for the inner one. Kotlin: for (x in channel) { } / consumeEach { }

    class channels

    source

    channels - the names of the four kinds of channel capacity.

    USAGE a := new channel<int>(); // rendezvous (the default) b := new channel<int>(16); // a buffer of 16 c := new channel<int>(channels.UNLIMITED); // send never waits d := new channel<int>(channels.CONFLATED); // only the newest element is kept

    capacity          send() when no receiver is waiting
---------------   -----------------------------------------------
RENDEZVOUS (0)    suspends until a receiver takes the element
n > 0             suspends only when n elements are waiting already
UNLIMITED         never suspends, the buffer grows
CONFLATED         never suspends, replaces the element that was waiting

    Kotlin equivalent: Channel.RENDEZVOUS, Channel.BUFFERED, Channel.UNLIMITED, Channel.CONFLATED.

    Fields

    RENDEZVOUSdecimalno buffer: every send meets a receive
    BUFFEREDdecimala buffer of a sensible default size
    UNLIMITEDdecimala buffer without a limit
    CONFLATEDdecimala buffer of one that always holds the newest element

    class closed_channel_exception

    base exception · source

    closed_channel_exception - thrown by channel.send() on a closed channel and by channel.receive() once a closed channel has nothing left.

    USAGE try { for( ;; ) { handle(inbox.receive()); } } catch(e: closed_channel_exception) { // the sender called close() and everything it sent was handled }

    Usually nicer than catching it: inbox.for_each({ item: message -> handle(item); }) or receive_or_null(), which end quietly when the channel is closed.

    Kotlin equivalents: ClosedSendChannelException and ClosedReceiveChannelException (one class here; catch clauses used to match the exact class only, and one name is easier to remember anyway).

    class produce<t>

    : coroutine_body · source

    produce<t> - start a coroutine that fills a channel, and get the receiving end of that channel.

    USAGE squares := produce<int>.start({ out: send_channel<int> -> for(i : decimal = 1; i <= 5; i++) { out.send(i * i); } }); // the channel is closed when the block returns

    squares.for_each({ n: int -> println("$n"); });  // 1 4 9 16 25
    // with a buffer and a state object (THE CLOSURE RULE: no captured locals)
lines := produce<string>.start(64, file, { out: send_channel<string>, s: object ->
    f := s as text_source;
    while(f.has_more()) { out.send(f.next_line()); }
});

    The coroutine is a child of the current coroutine or scope, like launch. The channel is closed when the block ends - normally, by an exception or by a cancellation - so the consumer's loop always ends. When the consumer calls cancel() on the channel the producer's next send() fails and the producer ends quietly. An exception of the block (other than that) fails the producer's job and with it the parent scope, as for launch.

    The language has no generic functions, so produce is a class whose static functions do the work; write the element type once: produce<int>.start(...). t must be an object type.

    Kotlin equivalent: produce { send(x) }.

    No locking: the fields are written before the coroutine is started and only read by its own fiber.

    interface send_channel<t>

    source

    send_channel<t> - the sending end of a channel: what a producer is given.

    USAGE def produce_numbers(out: send_channel<int>) { for(i : decimal = 0; i < 10; i++) { out.send(i); } out.close(); }

    Handing out only this interface makes it plain that the function sends and never receives. channel<t> implements it.

    Kotlin equivalent: kotlinx.coroutines.channels.SendChannel<E>.
