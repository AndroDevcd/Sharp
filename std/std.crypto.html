    class hash_work

    source

    HOW THE THREE WORK. They are built the same way (it has a name: the Merkle-Damgard construction):

    the data is cut into blocks of 64 bytes;
a small state (4, 5 or 8 numbers of 32 bits) starts at fixed values;
each block is stirred into the state by a fixed recipe of adds, rotations and bit operations;
the last block is padded: a 1 bit, zeros, and the length of the data in bits;
the state at the end, written out, is the fingerprint.

    Only the recipe - and whether numbers are written big end or little end first - differs. A 32-bit number lives in an _int64 here and is cut back to 32 bits (& M) after every add.

    class hmac

    source

    SIGNATURES WITH A SHARED SECRET (HMAC), and passwords (PBKDF2)

    signature := hmac.sha256_hex(secret, message);

    A hash of a message that only someone with the KEY can compute: a server that signs what it hands out (a session token, a webhook body, the parameters of an API call) can check later that it comes back unchanged and was signed by a holder of the key. Compare a signature you received with the one you computed using crypto.same(a, b), never ==.

    hmac.sha256(key, message)           32 bytes        key and message as bytes
hmac.sha256_hex(key, message)       as text         key and message as texts
hmac.sha1 / sha1_hex                20 bytes        (old APIs, TOTP codes)
hmac.md5 / md5_hex                  16 bytes        (older APIs still)

    PASSWORDS. To store a password, store this instead:

    salt := secure_random.bytes(16);                            // new for every password, stored beside it
stored := pbkdf2.sha256(password, salt, 100000, 32);        // 100000 rounds of hmac

    and to check one, compute it again from what was typed and the stored salt, and compare with crypto.same. The rounds make each guess cost someone who stole the stored values as much as it costs you once.

    Java comparison: Mac.getInstance("HmacSHA256"), SecretKeyFactory("PBKDF2WithHmacSHA256");
Python: hmac.new(key, msg, "sha256"), hashlib.pbkdf2_hmac.

    class secure_random

    source

    RANDOM NUMBERS NOBODY CAN GUESS

    key := secure_random.bytes(32);         // 32 random bytes
id := secure_random.hex(16);            // 32 characters, 0 to 9 and a to f
token := secure_random.token(24);       // 32 characters that are safe in an address (letters, digits, - and _)
roll := secure_random.below(6) + 1;     // 1 to 6, each as likely as the others

    std's rand() and seeded_random are for games and simulations: fast, and the same seed gives the same numbers - so whoever sees a few of them can work out the rest. Keys, tokens, salts, session ids and passwords have to come from here: the operating system's own generator, which collects what cannot be predicted (the timing of the hardware) and is what the system's own encryption uses.

    Windows     BCryptGenRandom (bcrypt.dll)
Linux       getrandom

    Throws illegal_state_exception when the system gives none (which does not happen on a working system).

    Java comparison: java.security.SecureRandom; Python: secrets.token_bytes / token_urlsafe.

    class sha256

    source

    HASHES: a fingerprint of any amount of data

    sha256.hex("hello")                 "2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824"
sha256.bytes("hello")               the same 32 bytes, not written out
sha256.hex_of(bytes)                of bytes instead of a text
sha256.hex_of_file(new file("a.zip"))
    // data that comes in pieces
running := new sha256();
running.add("first part");
running.add_bytes(more);
print(running.hex());

    The same data always gives the same fingerprint; any change to it gives a completely different one; and nobody can make data to fit a fingerprint. That is what downloads are checked with, what signatures and tokens are built from (hmac, in hmac.sharp), and how a file is named by its content.

    sha256      32 bytes. The one to use.
sha1        20 bytes. Broken for security (two different files with one fingerprint
            have been made); still what git, WebSocket handshakes and old APIs ask for.
md5         16 bytes. Broken the same way, long ago; for old checksums and ETags only.

    NOT FOR PASSWORDS as they are: a fingerprint is fast to compute, so every password can be tried. Passwords go through pbkdf2 (hmac.sharp).

    All three are written in Sharp (no library is called); a megabyte takes a moment, not an instant.

    Java comparison: MessageDigest.getInstance("SHA-256"); Python: hashlib.sha256(data).hexdigest().
