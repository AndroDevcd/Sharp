    class array_iterator<T>

    : iterator<T> · source

    An iterator over the elements of an array, from a start index up to (not including) an end index.

    It is what the array backed collections (stack, queue, deque, hash_set, the maps, ...) return from iterator(): they hand it a snapshot of their elements, so the collection may be changed while the iterator is in use without disturbing the walk (the iterator keeps showing the elements as they were when it was created).

    It can also be used directly to walk a plain array:

    it := new array_iterator<string>(names);
while(it.has_next()) println(it.next());

    class arrays<T>

    source

    Static helpers for arrays of OBJECTS (int[], string[], my_class[], ...): sorting, searching, copying, comparing. Nothing here needs an instance; name the element type and call the function:

    words := new string[] { "pear", "fig", "apple" };
arrays<string>.sort(words, { a: string, b: string -> (decimal) return a.size() - b.size(); });
arrays<string>.index_of(words, "fig");        // 0

    For arrays of native numbers (decimal[]) use var_arrays instead.

    Ordering is always given as a comparison function:

    compare(a, b) < 0     a sorts before b
compare(a, b) == 0    a and b sort the same
compare(a, b) > 0     a sorts after b

    Equality (index_of, contains, equals, count) uses ==: numbers and strings compare by value, other objects by identity.

    class bit_set

    source

    A growable row of bits, each either on (1) or off (0), addressed by an index that starts at 0. It is the compact way to keep a yes/no flag for a large range of small numbers (visited markers, a sieve, sets of ids): 30 flags are packed into every native number.

    seen := new bit_set();
seen.set_bit(3);
seen.set_bit(1000);         // grows automatically
seen.test(3);               // 1
seen.test(4);               // 0  (bits that were never touched are off)
seen.cardinality();         // 2  (how many bits are on)

    Two bit sets can be combined bit by bit with and_with / or_with / xor_with / and_not, which makes a bit_set a fast set of small integers (intersection, union, difference).

    Storage: an array of native numbers ("words"), 30 bits used in each. (30 rather than 32 or 64 keeps every word a small positive integer, for which the shift and bit operators of the VM are exact.)

    (set is a keyword of the language, hence the names set_bit / clear_bit.)

    class collections<T base _object_>

    source

    LISTS OF LISTS: chunked, windowed, flatten.

    rows := collections<int>.chunked(numbers, 3);      // [[1,2,3],[4,5,6],[7]]
pairs := collections<int>.windowed(numbers, 2);    // [[1,2],[2,3],[3,4], ...]
all := collections<int>.flatten(rows);             // [1,2,3,4,5,6,7]

    Everything else of this kind - filter, map, sorted_by, group_by ... - is a function of the list itself (collection_functions.sharp): numbers.filter { it > 3 }. These three are static functions of a class because a function of every list cannot give a list of lists.

    The source is any collection (loopable<T>): a list, a linked_list, a deque, a hash_set, a tree_set ... It is never changed.

    Limitation: T has to be an object type; native decimal cannot be used.

    class deque<T>

    : loopable<T>, iterable<T> · source

    A double ended queue ("deck"): elements can be added and removed at both the front and the back in O(1).

    It is backed by an array that is used as a ring buffer: head is the array index of the first element and the elements continue from there, wrapping around to index 0 when they reach the end of the array. Nothing is moved when an element is added or removed at either end. When the array is full it is replaced by one twice the size (so adding is O(1) on average).

    d := new deque<int>();
d.add_last(2);  d.add_last(3);  d.add_first(1);      // 1 2 3
d.remove_first();                                    // 1
d.remove_last();                                     // 3

    Unlike a linked_list, reading by index (at) is O(1) as well.

    Limitation: the element type has to be an object type; native types such as decimal cannot be used as T.

    class hash_set<T base _object_>

    : loopable<T>, iterable<T> · source

    A collection that holds every element at most once and answers "is x in here?" in O(1) on average, however many elements it holds.

    seen := new hash_set<string>();
seen.add("a");          // 1: added
seen.add("a");          // 0: was already there
seen.contains("a");     // 1
seen.size();            // 1

    Elements are found through hash() and compared with ==, so the element type must give equal elements the same hash - int, string and the other std value types do. For your own classes override hash().

    Looping over the set (foreach, iterator, to_array, to_list) visits the elements in the order they were first added. That order is a guarantee: the set is built on linked_hash_map (each element is a key), which costs two extra references per element and buys predictable output.

    Besides the single element operations there are the classic set operations: union, intersect, subtract, contains_all.

    Limitation: the element type has to be an object type; native types such as decimal cannot be used as T.

    class immutable_list<T>

    : loopable<T>, iterable<T> · source

    A list that cannot be changed after it was created: it has functions to read, search and loop, and none to add, replace or remove. Hand one out when other code should be able to look at your elements but must not be able to modify your collection.

    class team {
    private members := new list<string>();
    def roster() : immutable_list<string> {
        return new immutable_list<string>(members);
    }
}

    The elements are COPIED when the immutable_list is created (O(n)), so later changes to the original collection do not show through, and the arrays it hands out (to_array, foreach) are copies too. Note that only the list is frozen: if the elements themselves are mutable objects, they can still be changed through their own functions.

    "Changing" functions return a NEW immutable_list and leave this one as it is: plus, sub_list, reversed.

    Limitation: the element type has to be an object type; native types such as decimal cannot be used as T.

    interface iterable<T>

    source

    @interface iterable

    Implemented by everything that can hand out an iterator over its elements. All collections of std.collections implement it, which makes it possible to write a function once and use it with any of them:

    def total(numbers: iterable<int>) : decimal {
    sum : decimal = 0;
    it := numbers.iterator();
    while(it.has_next()) sum += it.next().value;
    return sum;
}

    interface iterator<T>

    source

    @interface iterator

    The uniform way to walk over the elements of any collection in std.collections, one element at a time:

    it := names.iterator();
while(it.has_next()) {
    name := it.next();
    ...
}

    Every collection in this module hands out an iterator through its iterator() function (see the iterable interface). Collections also implement loopable, so the shorter foreach(name in names) works too; an iterator is the tool for when a loop has to be paused, resumed, or passed to another function.

    An iterator is a one-way, one-use cursor: once has_next() answers 0 it is finished, and a new one has to be requested to walk the collection again.

    class linked_hash_map<K base _object_, V>

    : loopable<map_entry<K, V> >, iterable<map_entry<K, V> > · source

    A hash map that remembers the order in which its keys were first added. Looking a key up, adding and removing are O(1) on average, like any hash map, and looping over the map always visits the pairs oldest first:

    ages := new linked_hash_map<string, int>();
ages.put("tom", 31);
ages.put("ann", 27);
ages.put("tom", 32);                  // replaces the value, keeps the position
foreach(entry in ages)
    println(entry.key + " " + entry.value);       // tom 32, ann 27

    How it works: an array of buckets, each bucket a chain of nodes whose keys hash to that slot (key.hash() picks the bucket, == finds the key inside it). Every node is additionally part of one long doubly linked chain that runs through all pairs in insertion order. When the map holds more than 0.75 pairs per bucket the bucket array is doubled.

    Keys: the key type must give equal keys the same hash() - int, string and the other std value types do. For your own classes override hash() (and operator== if two different objects should count as the same key).

    Limitation: key and value types have to be object types; native types such as decimal cannot be used.

    class priority_queue<T>

    : loopable<T>, iterable<T> · source

    A queue that always hands out its SMALLEST element first, whatever order the elements were added in. "Smallest" is decided by a comparison function given to the constructor:

    compare(a, b) < 0     a comes out before b
compare(a, b) == 0    a and b have the same priority
compare(a, b) > 0     a comes out after b
    // smallest number first
pq := new priority_queue<int>({ a: int, b: int -> (decimal) return a.value - b.value; });
pq.add(5);  pq.add(1);  pq.add(3);
pq.poll();      // 1
pq.poll();      // 3

    To get the LARGEST first, turn the comparison around (b.value - a.value).

    Implementation: a binary heap stored in an array. The element at index i has its children at 2i+1 and 2i+2, and every element is <= its children, so the smallest one is always at index 0. add and poll are O(log n), peek is O(1).

    Elements with the same priority come out in no particular order (a heap is not stable).

    Looping (foreach, iterator, to_sorted_array) visits the elements in priority order without removing them; that costs O(n log n) because a sorted copy is made.

    Limitation: the element type has to be an object type; native types such as decimal cannot be used as T.

    class tree_map<K, V>

    : loopable<map_entry<K, V> >, iterable<map_entry<K, V> > · source

    A map that keeps its keys SORTED. Looking a key up, adding and removing are O(log n); looping over the map visits the pairs in ascending key order; and because the keys are ordered the map can also answer questions a hash map cannot: the smallest / largest key, the nearest key below or above a value, all keys inside a range.

    The order is decided by a comparison function given to the constructor:

    compare(a, b) < 0     a sorts before b
compare(a, b) == 0    a and b are the same key
compare(a, b) > 0     a sorts after b
    prices := new tree_map<int, string>({ a: int, b: int -> (decimal) return a.value - b.value; });
prices.put(30, "c");  prices.put(10, "a");  prices.put(20, "b");
prices.first_key();          // 10
prices.floor_key(25);        // 20  (largest key <= 25)
prices.ceiling_key(25);      // 30  (smallest key >= 25)
foreach(entry in prices) ...  // 10, 20, 30

    Two keys are "the same key" exactly when compare returns 0 for them; == and hash() are not used.

    Implementation: an AVL tree - a binary search tree in which the heights of the two sub trees of every node differ by at most 1, which keeps the tree at most ~1.44 * log2(n) levels deep. After every insert and remove the path back to the root is checked and repaired with rotations. All algorithms are written as loops (nodes know their parent), so the depth of the call stack does not grow with the size of the map.

    Limitation: key and value types have to be object types; native types such as decimal cannot be used.

    A set (every element at most once) that keeps its elements SORTED. Adding, removing and "is x in here?" are O(log n); looping visits the elements in ascending order; and the set can find the smallest / largest element, the nearest element below or above a value, and all elements inside a range.

    The order is decided by a comparison function given to the constructor (negative: a sorts before b, zero: same element, positive: a sorts after b):

    primes := new tree_set<int>({ a: int, b: int -> (decimal) return a.value - b.value; });
primes.add(7);  primes.add(2);  primes.add(5);  primes.add(2);
primes.size();          // 3
primes.first();         // 2
primes.higher(5);       // 7   (smallest element > 5)
foreach(p in primes)    // 2, 5, 7

    Two elements are "the same" exactly when the comparison returns 0 for them; == and hash() are not used.

    It is built on tree_map (an AVL tree; each element is a key).

    Limitation: the element type has to be an object type; native types such as decimal cannot be used as T.

    class var_arrays

    source

    Static helpers for arrays of NATIVE numbers (decimal[]): sorting, searching, copying, and the usual aggregates (min, max, sum, average).

    samples := new decimal[4];
samples[0] = 3;  samples[1] = 1.5;  samples[2] = 9;  samples[3] = 2;
var_arrays.sort(samples);                   // 1.5, 2, 3, 9
var_arrays.binary_search(samples, 3);       // 2
var_arrays.sum(samples);                    // 15.5

    For arrays of objects (int[], string[], ...) use arrays<T> instead.
