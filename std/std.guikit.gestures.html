    class reorder

    source

    reorder - drag the children of a column into a new order. Asked for with .reorderable { from, to -> ... } on a column.

    column {
    for(...) { task_card(t); }
}.animate_items().reorderable { from: _int64, to: _int64 -> model.move(from, to); };

    Press a row and HOLD (a long press) to pick it up: it lifts above the others. Drag it up or down and the rows it passes move aside to show where it would land. Let go, and the function is called with where the row was and where it is now - both counted among the column's children as they are on the screen. The function changes the list; the screen is built again from it, and the row settles into its new place.

    A quick drag without holding first is not a pick-up: it scrolls the list the column is in, as before.

    FRAMEWORK USE: the column owns one of these and calls wire_all() whenever it arranges its children. (Android: ItemTouchHelper with onMove. Compose: no built-in; libraries do exactly this with detectDragGesturesAfterLongPress.)

    HOW IT WORKS: nothing is laid out differently while a row is carried. The carried row and the rows that step aside are only PAINTED somewhere else (view.shift_y). When the list really changes, the new layout puts every row in its new slot, finds it is already being painted there, and has nothing left to animate (glide.sharp) - so the drop is seamless.

    class swipe_row

    base widget : behavior · source

    swipe_row - a row you can push off the screen sideways to get rid of it. Made with swipe_to_dismiss(...).

    swipe_to_dismiss({ -> model.remove(t); }) {
    task_card(t);
}.behind("Delete");

    Drag the row left or right: it follows the mouse, and the colour behind it shows what letting go will do. Let go past a third of its width and it flies the rest of the way, then the action runs. Let go sooner and it glides back.

    THE ACTION MUST REMOVE THE ROW (take the item out of the list the screen is built from). The row itself does not vanish - like everything here, the screen shows what the state says.

    In a list that scrolls, an up-and-down drag still scrolls the list: the row decides from the first movement which way the drag goes, and hands a vertical one on to the scroller around it. (Compose: SwipeToDismissBox. Android: ItemTouchHelper with onSwiped.)
