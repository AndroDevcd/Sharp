    class menu_box

    base widget : behavior · source

    menu_box - the list of choices of a context menu: the thing that appears at the mouse when something is right-clicked. Made with menu(...).

    opened := state(0);
    row(modifier().right_click { opened.value = 1; }) { text(file.name); };
    menu(opened) {
    menu_item("Open") { open(file); };
    menu_item("Rename") { rename(file); };
    divider();
    menu_item("Delete") { remove(file); };
}

    The menu is there while its state is not 0, at the place the mouse was when it opened. Choosing an item runs its action and closes the menu; a click anywhere else, or Escape, closes it without choosing. (Android: PopupMenu / a context menu. HTML: the contextmenu event.)

    menu_item(...) ONLY WORKS INSIDE menu { }: written anywhere else it stops the program with an error that says so (scope.inside). Other widgets - a divider, a caption - may sit between the items.

    HOW IT WORKS: menu(...) makes a popup placed at the mouse (popup.sharp, POPUP_AT_MOUSE) and, inside it, this box: a column with a border and a shadow. The box keeps the function that closes the menu, so that an item - which looks its menu up through the scope - can close it after running.

    class popup

    base widget : behavior, floater, stateful · source

    popup - content that floats ABOVE the page instead of sitting in it: the machinery under dialog(...) and dropdown(...).

    A popup is an ordinary widget in the tree - it is made by build() like everything else, and it exists exactly while your state says it is open. There is no show() or dismiss() to call and no second window:

    confirm := state(0);
button("Delete") { confirm.value = 1; };
dialog(confirm) {                          // there while confirm.value is 1
    text("Delete this file?");
    button("Yes") { remove(); confirm.value = 0; };
}

    (Android does dialogs and popups as separate windows with imperative show() / dismiss(), which is where much of their complexity comes from. Keeping them in the one tree, driven by state, is the lesson taken from Compose - and then simplified: Compose still opens a window for a Dialog.)

    HOW IT FLOATS

    In the PAGE the popup takes no room at all (it measures as 0 x 0), and it is a floater: the view does not paint or hit-test its children in the normal walk. Instead, when the page is arranged the popup tells the host "I am open" (ui_host.add_overlay). The host then, after the page:

    - has each open popup place its content in the WINDOW (place_content):
  centred, or under its anchor - flipped above it when there is no room
  below, and kept inside the window;
- paints them on top of the page, in the order they were opened;
- asks them FIRST where the mouse is. A click outside the topmost popup
  closes it and goes no further (it does not also press what is behind);
  Escape closes it too.

    "Closing" is asking: the popup calls the dismiss function it was given, which sets your state back to 0; the rebuild that follows simply does not make the popup again. The state stays yours.

    The ANCHOR of a POPUP_BELOW popup is its parent in the tree: the container it was made in. dropdown puts its closed box and its popup into one small stack for exactly that reason.
