    class char_array

    : loopable<_int8> · source

    A thin wrapper around a raw array of characters (_int8[]). The compiler and the console functions use it to accept "anything that is a row of characters" - a string literal, a number array, a char[], a string - through its constructors, so those must stay as they are.

    On top of that it is a small MUTABLE character buffer of fixed length: unlike string, whose text methods return new strings, the methods here (put, fill, reverse, sort, to_upper ...) change the characters in place. To change the length use a string_builder instead.

    chars := new char_array("hello");
chars.put(0, 'j');
chars.reverse();
chars.to_string()        "ollej"

    Sharing: char_array(_int8[]), char_array(char_array) and char_array(string) do NOT copy - the new object works on the same characters as its source, so changing one changes the other. Call duplicate() for an independent copy. The other constructors convert and therefore always copy.

    data is null for an empty array; every method accepts that. Positions and yes/no answers are native numbers; -1 means "not found".

    class character

    source

    character

    Questions about, and conversions of, single characters. All functions are static: character.is_digit('7').

    A character is its code, a plain number: a literal ('a') or what text.char_at(i) and text.data[i] give (for a char object: its value, or the same questions asked of the object - c.is_digit()). A question is answered with a bool; a conversion gives the code.

    These are the character questions of the whole library.

    Characters are single bytes and only ASCII is classified: a byte outside of 0..127 (part of a UTF-8 sequence) is never a letter, digit, space or punctuation mark, and the case conversions leave it alone.

    class dictionary<k base _object_, v base _object_>

    : loopable<pair<k,v> > · source

    Values kept under keys, in the order they were added. It is what a dictionary literal makes:

    ages := { "ann" : 31, "bob" : 45 };          // dictionary<string, int>
none := { as <string, int> : };              // an empty one, its types written

    A value is read and written through its key, in brackets:

    ages["ann"];                                 // 31
ages["cy"] = 28;                             // a new key, added at the end
ages["ann"] = 32;                            // an old key: its value is replaced, its place kept
ages["dee"];                                 // no such key: no_such_element_exception

    and, without an exception when the key is missing:

    ages.at("dee");                              // null
ages.at_or_default("dee", 0);                // 0
ages.contains_key("dee");                    // false
    ages.remove("bob");
ages.size();                                 // 2
foreach(entry in ages) println(entry.first + " = " + entry.second);     // in the order they were added
ages.keys();   ages.values();                // lists, in that order too

    The types of a literal are those of its first pair, as name := value would make them: text is a string, a whole number an int, a number with a fraction a double. Write as <key, value> first for other types. When the same key is written twice, the later value is kept.

    How it works: a hash table (key.hash() picks a bucket, a bucket's entries form a chain searched with ==), and every entry also knows the entry added before and after it, which is the order a loop follows. Reading, writing and removing are O(1) on average.

    Keys: equal keys must give the same hash() - string, int and the other value types of the library do. Not thread safe. (Python: dict. Kotlin: LinkedHashMap, mutableMapOf. JavaScript: Map.)

    class hash_map<k base _object_, v base _object_>

    source

    A map from keys to values with O(1) average lookup: put a value under a key, get it back with at().

    ages := new hash_map<string, int>();
ages.put("ann", 31);
ages.at("ann");             // 31
ages.at("bob");             // null: no such key
ages.contains_key("ann");   // true
ages.remove("ann");
foreach(entry in ages.entries()) println(entry.key + " is " + entry.value);

    How it works: an array of buckets; key.hash() picks the bucket and the entries of one bucket form a chain that is searched with ==. When the map holds more than threshold (0.75) entries per bucket the bucket array grows and every entry is moved to its new bucket.

    What keeps it quick: a key is hashed once per call; every entry keeps its key's hash, so growing the table hashes nothing again and a chain is searched by comparing numbers first, keys (==) only when the numbers agree; and the bucket of a hash is found with & when the number of buckets is a power of two - which it is unless a map is made with another number - and with % otherwise. Both ways give the same bucket.

    Keys: the key type must give equal keys the same hash() - int, string and the other std value types do.

    The order in which keys(), values() and entries() list the entries is the order of the buckets: it looks random and changes when the map grows. Use std.collections#linked_hash_map for insertion order or std.collections#tree_map for sorted keys.

    Not thread safe; hash_table is the same map with a lock around every call.

    class hash_table<k base _object_, v base _object_>

    A hash_map that several threads may use at the same time: the same functions, each run inside lock(self).

    hits := new hash_table<string, int>();
hits.put("home", 1);

hits.contains_key("about");     // false

    Each single call is atomic; a SEQUENCE of calls is not ("if it is not in the table, put it" can still be interleaved with another thread - that one is put_if_absent, which is a single call).

    keys(), values() and entries() give new lists: loop over them while other threads go on changing the table.

    class list<T>

    : loopable<T> · source

    A growable, array backed list: the general purpose collection of the library. Elements keep the order they were added in and are reached by their position (0 = first).

    names := new list<string>();
names.add("ann");
names.add("bob");
names.at(1);                    // "bob"
foreach(name in names) ...      // ann, bob

    Costs: at / put / add are O(1) (add occasionally O(n) when the array has to grow); insert / remove_at / index_of are O(n).

    The rest of what a list can do - filter, map, sorted_by, group_by, binary search, ranges, bulk removal - is in collection_functions.sharp, as functions of the list: names.filter { it.size() > 3 }.

    Elements are compared with == (index_of, remove): numbers and strings by value, other objects by identity.

    Limitation: the element type has to be an object type. list<decimal> does not compile at the moment (the class uses T?).

    Not thread safe: see synced_list for a list that several threads may use.

    def sort(compare: (T, T)(decimal))

    Sort the list in place. compare(a, b) answers a negative number when a sorts before b, 0 when they sort the same, a positive number when a sorts after b:

    numbers.sort({ a: int, b: int -> (decimal) return a.value - b.value; });

    O(n log n) for any input, and stable - elements that compare as equal keep their order (see sort_array).

    static def sort_array(items: T[], count: _int64, compare: (T, T)(decimal))

    Sort the first count elements of an array in place. This is the merge sort of the library: list.sort, arrays<T>.sort and the sorted functions of a list all come here.

    Written bottom-up (loops only, no recursion): sorted runs of length 1, 2, 4, 8, ... are merged pairwise until one run covers everything. Always O(n log n) comparisons, also for input that is sorted or reversed, and stable. Uses one spare array of count elements.

    A new array with the elements, in order. Unlike get_elements() it never returns null: an empty list gives an array of length 0. O(n).

    class seeded_random

    source

    A random number generator written in Sharp whose whole sequence is decided by its seed: two generators made with the same seed produce exactly the same numbers, on every machine and in every run. Use it when results must be reproducible - tests, simulations, procedurally generated content, replays.

    rng := new seeded_random(42);
roll : decimal = rng.next_int(1, 6);        // a die: 1 .. 6
chance : decimal = rng.next_double();       // 0 <= chance < 1
rng.shuffle(cards);

    (rand(), rand_int() ... in std/random.sharp use the runtime's generator instead, which is seeded from the clock unless set_seed() is called.)

    ALGORITHM: xorshift32 (George Marsaglia, 2003). The state is one 32-bit word x, never 0, and each step is

    x ^= x << 13;     x ^= x >> 17;     x ^= x << 5;      (all modulo 2^32)

    It visits every value 1 .. 2^32 - 1 once before repeating. It is fast and good enough for games, tests and simulations, but it is NOT cryptographically secure: do not use it for passwords, keys or tokens.

    The class does no locking; give each thread its own generator.

    def next_gaussian(): decimal

    A normally distributed number with mean 0 and standard deviation 1 (the "bell curve": about 68% of the results lie in -1 .. 1).

    Algorithm: the Marsaglia polar method. Pick points (u, v) in the square -1 .. 1 until one falls inside the unit circle (s = u^2 + v^2 with 0 < s < 1); then u * f and v * f with f = sqrt(-2 log(s) / s) are two independent normal values. The second one is kept for the next call.

    class string_builder

    : loopable<_int8> · source

    Builds a string piece by piece in a buffer that grows by doubling, so adding n characters costs about n copies in total. Use it instead of += on a string inside a loop: every += on a string copies the whole string again.

    sb := new string_builder();
sb.append("x = ").append_int(42).append_line();
text := sb.build();

    The buffer (data) is usually larger than the text; only the first size() characters are in use. Every append returns the builder itself so calls can be chained.

    This file holds the core: creating, appending, comparing and reading back. More operations are added to the class from std/text/builder/: string_builder_edit.sharp insert, delete, replace_range, reverse, clear, set_length, append_line, append_int, append_number, append_repeat string_builder_query.sharp length, capacity, char_at, index_of, contains, slice

    A builder is not safe to share between threads without a lock.
