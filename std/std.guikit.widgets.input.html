    class button

    base widget : behavior, shows_words · source

    button - words you can click. Made with button(...).

    button("Save") { save(); }
button("Cancel") { close(); }.outline()
button("Delete", modifier().enable(can_delete.value)) { remove(item); }.danger()

    .outline() / .plain() / .danger() another look (default: filled) modifier().enable(0) greyed out, cannot be clicked

    The button reacts to the mouse by itself (lighter under it, darker while pressed) and can be reached with Tab and clicked with Enter or Space.

    HOW IT WORKS: a button has no input code of its own. Its view carries the click handler (view.on_click), and the host does the pressing, releasing and keyboard clicking for every view that has one. The button only decides how big it is and how it looks for the view's hovered / pressed flags. (Compose: Button / OutlinedButton / TextButton. Android: Button.)

    class checkbox

    base widget : behavior, shows_words, on_or_off · source

    checkbox - a box you tick, with words next to it. Made with checkbox(...).

    agreed := state(0);                                     // 0 = off, 1 = on
checkbox("I agree to the terms", agreed)
button("Continue", modifier().enable(agreed.value)) { go(); }

    WITH A BLOCK, THE CAPTION IS WIDGETS instead of words:

    checkbox(agreed) { text("I agree to the"); text("terms").color(blue); }

    The checkbox is BOUND to the state: it shows the state's value, and a click flips it (0 <-> 1). Because the state changed, everything built from it is rebuilt - the button above enables itself. You never ask the checkbox whether it is ticked; you read the state. (This is "single source of truth": the value lives in ONE place, your state, and the widget is only a view of it. Compose: Checkbox(checked, onCheckedChange).)

    class dropdown

    base composable · source

    dropdown - pick one of several named choices from a menu that drops down.

    size := state(1);                       // which option is chosen: 0 is the first
    dropdown(size) {
    option("Small");
    option("Medium");
    option("Large");
}

    WITH A BLOCK, AN OPTION IS WIDGETS instead of words - in the list, and in the closed box while it is the chosen one:

    option { image("flags/se.png", modifier().size(18, 12)); text("Sweden"); }

    Closed, it is a box showing the chosen option. A click opens the list under it (above it, when there is no room below); choosing an option writes its number into the state and closes the list; a click anywhere else, or Escape, closes it without choosing. (Android: Spinner. Compose: ExposedDropdownMenuBox. HTML: select.)

    option(...) ONLY WORKS INSIDE dropdown { }: written anywhere else it stops the program with an error that says so (scope.inside).

    THIS WIDGET IS BUILT FROM THE FRAMEWORK'S OWN PARTS - it is a composable, exactly like one you would write:

    - whether the list is open is a state of its own (open). It is the dropdown's business, not the program's, and because it is a composable state it survives the rebuilds that typing or clicking elsewhere cause; - build() returns a stack holding the closed box (a clickable row) and, while open, a popup placed under that stack (popup.sharp).

    Nothing here reaches below the public API, so it doubles as an example of making your own compound widget.

    class form

    source

    form - the rules a set of fields must pass before something is saved, and what to tell the user when they do not.

    class new_task_model base view_model {          // (or any class: the form is plain logic)
    title    := state("");
    estimate := state("");
    rules    := form();
    new_task_model() {
    rules.require(title, "Give the task a title");
    rules.rule(estimate, "A number above 0") { v: string -> return is_positive(v); };
}
        def save() {
        if(rules.check() == 1) { ... }          // all fine: go ahead
    }
}
    // the screen only shows what the form found:
text_field(model.title).label("Title").error(model.rules.problem_of(model.title));

    check() runs every rule and remembers, per field, the message of the first rule it broke. problem_of(field) gives that message ("" when the field is fine) - and because it reads a state, the screen shows the red text the moment check() ran, and loses it again when a later check() passes.

    Nothing is shown before the first check(): a form that is red before the user typed anything is rude. (Android: TextInputLayout.setError driven from a ViewModel. Compose: the same, with isError / supportingText.)

    class radio

    base widget : behavior, shows_words, on_or_off · source

    radio - one choice out of several: a round dot with words next to it. Made with radio(...).

    size := state(1);                       // which one is chosen
    radio("Small",  size, 0);

    WITH A BLOCK, THE CAPTION IS WIDGETS instead of words:

    radio(size, 2) { text("Large"); chip("popular"); }

    All the radios of one group share ONE state: each radio stands for a number (its last argument), shows itself chosen while the state holds that number, and a click writes its number into the state. There is no "radio group" object to create - the shared state IS the group, and reading it tells you the choice. (Compose: RadioButton(selected, onClick), with the selection hoisted the same way.     class slider

    base widget : behavior, pointer_target, key_target, has_value · source

    slider - pick a number by dragging a knob along a track. Made with gui.slider(...).

    volume := state(0.5);
gui.slider(volume, 0, 1)                    // from 0 to 1
gui.slider(age, 0, 120).whole()             // only whole numbers
gui.text("volume: " + volume.value)

    Bound to a decimal state: dragging writes the state, and whatever was built from it follows while you drag. With the keyboard focus on it, the left and right arrow keys move it a step.

    HOW DRAGGING WORKS: the slider is a pointer_target. From the press until the release the host sends every mouse move to it - also when the mouse strays off the track - and each one is turned into a value: how far along the track the mouse is, as a fraction, scaled into low .. high. (Compose: Slider. Android: SeekBar. HTML: input type=range.)

    class tab_strip

    base widget : behavior · source

    tabs - a strip of titles, one of them chosen: the switch between the pages of a screen.

    page := state(0);                       // which tab is chosen: 0 is the first
    tabs(page) {
    tab("Overview");
    tab("Files");
    tab("Settings");
}
    if(page.value == 0) { overview(); }
else if(page.value == 1) { files(); }
else { settings(); }

    WITH A BLOCK, A TAB'S TITLE IS WIDGETS instead of words:

    tab { text("Inbox"); badge(unread.value); }

    The strip only CHOOSES: it writes the number of the clicked tab into the state. Showing the right page for that number is ordinary code of yours, as above. (Compose: TabRow + Tab. Android: TabLayout.)

    tab(...) ONLY WORKS INSIDE tabs { }. A tab has no meaning anywhere else, and written elsewhere it stops the program with an error that says so (scope.inside).

    HOW IT WORKS: tab_strip is a row (it uses the same flex algorithm). Each tab is a small widget of its own; a tab's NUMBER is simply its position among the strip's children, worked out when it is clicked or painted, so tabs can be added in a loop or left out by an if without numbering them.

    class text_area

    base widget : behavior, key_target, pointer_target, wheel_target, stateful, shows_words, has_caption · source

    text_area - a box for text of several lines: notes, a description, a message. Made with text_area(state).

    notes := state("");
text_area(notes, modifier().fill_width().height(140))
    .label("Notes")
    .hint("Anything worth remembering")
    .limit(500);

    Long lines wrap at the box's edge, between words where it can. Enter starts a new line. When there is more text than fits, the box scrolls: with the wheel, and by itself to keep the cursor in view.

    Everything a text_field does with the keyboard and mouse works here too: Shift + arrows and dragging select, a double click selects a word, Ctrl+A / C / X / V, Home and End (of the line). Up and Down move between lines and remember the column they came from, the way every editor does.

    Without a height from a modifier it is four lines tall. (Android: EditText with inputType textMultiLine. Compose: TextField with singleLine = false.)

    HOW IT WORKS

    The text is ONE string, with a line feed (byte 10) where Enter was pressed. What is on the screen is a list of LINES worked out from it (lines): each says "bytes from..to of the text are on this row". A paragraph that is too wide becomes several lines; that wrapping exists only in the list - the string never gets line feeds of its own.

    The list is worked out again only when the text or the width changed (wrapped_text, wrapped_width remember what it was made for).

    The cursor and the selection are positions in the STRING (bytes), exactly as in text_field. To paint them, a position is turned into "which line, how far across"; to place them with the mouse, a point is turned back into a position.

    class text_field

    base widget : behavior, key_target, pointer_target, stateful, shows_words, has_caption · source

    text_field - a box to type one line of text into. Made with text_field(...).

    name := state("");
text_field(name).hint("Your name").on_submit({ -> greet(); })
text("Hello, " + name.value)
    text_field(secret).password()               // shows dots instead of the letters
text_field(amount).numbers_only().limit(8)  // digits, a point and a minus; at most 8 letters

    .hint(words) grey words shown while the field is empty .on_submit(action) run when Enter is pressed in the field .password() hide what is typed (and refuse to copy it) .numbers_only() take only what a number is written with .limit(n) at most n letters

    Bound to a text state: every key writes the new text into the state, so anything built from it follows as you type.

    EDITING, the way every text box works:

    click                       put the cursor there
drag                        select from where the press began
double click                select the word
Left / Right / Home / End   move the cursor      (+ Shift: select as it moves)
Backspace / Delete          remove the selection, or one letter
typing                      replaces the selection
Ctrl+A                      select everything
Ctrl+C / Ctrl+X / Ctrl+V    copy / cut / paste - the system clipboard,
                            shared with every other program

    WHAT LIVES WHERE

    The TEXT is yours: it is in your state, and the field never keeps a copy. The CURSOR, the SELECTION and how far a long text is scrolled sideways are the field's own memory. Typing changes your state, which rebuilds the screen and makes a NEW field object - so the field is stateful and the new one adopts those from the old. That, and the host moving the keyboard focus across the rebuild, is why you can keep typing.

    THE SELECTION is two positions: anchor, where it began, and cursor, where it has got to. Everything between them is selected, whichever comes first; with no selection the anchor is -1. Shift+arrow moves the cursor and leaves the anchor; a plain arrow drops the anchor.

    POSITIONS are counted in BYTES into the text. Sharp strings are UTF-8, where a letter like an accented e takes two bytes; the cursor only ever stops BETWEEN letters, never inside one (step_back / step_forward skip the bytes that continue a letter). (Compose: TextField. Android: EditText. HTML: input type=text.)

    class toggle

    base widget : behavior, stateful, on_or_off · source

    toggle - an on/off switch. Made with gui.toggle(...).

    dark_mode := state(1);                  // 0 = off, 1 = on
gui.row().gap(12)
    .add(gui.text("Dark mode"))
    .add(gui.spacer())
    .add(gui.toggle(dark_mode))

    Bound to a state like a checkbox: it shows the state's value and a click flips it. The knob SLIDES to its new side instead of jumping.

    HOW THE SLIDE WORKS: slid is where the knob is drawn, from 0 (off side) to 1 (on side). Every frame it moves a little toward where the state says it should be, and while it is not there yet the toggle asks the host for another frame (request_frame). When it arrives it stops asking, and the app goes back to sleep. slid is the toggle's own memory - not your state - so a rebuilt toggle adopts it from the one it replaces; otherwise every rebuild would snap the knob to the end. (Compose: Switch. Android: SwitchCompat.)
