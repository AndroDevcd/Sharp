    class chart

    base widget : behavior, stateful, pointer_target, overlay_painter · source

    chart - numbers as bars and lines. Made with chart(...).

    chart(modifier().fill_width().height(240)) {
    bars("Sales", sales).corner(6);
    line("Target", target).curved().dots(4);
        x_axis(months);
    y_axis().ticks(5);
    grid_lines().dashed();
    legend();
    marker();
}.enter(motion.grow().stagger(0.04));

    WHAT GOES IN THE BLOCK

    bars(...) line(...) the data: any number of each, drawn in the order written (series.sharp) x_axis(...) y_axis() the words along the bottom and the numbers up the side (parts.sharp) grid_lines() level lines behind the marks legend() the names of the series marker() the place under the mouse is marked and its numbers are shown

    Each of them only works inside chart { }; written anywhere else it stops the program with an error that says so. Ordinary if and for work in the block, as in every block of this library.

    EACH OF THEM TAKES A BLOCK OF ITS OWN, and then what it would have written is built from widgets instead - any widgets, your composables too:

    x_axis(months) { text(it.words).size(13); if(it.index == best) { chip("best"); } }
legend { text(it.name).color(it.tint!!); }
marker { text(months[it.index]).bold(); progress(share[it.index]); }
bars("Sales", sales) { if(it.value >= goal) { chip("goal"); } }

    AND ANY OTHER WIDGET CAN BE WRITTEN IN THE BLOCK. It is laid over the marks, where its modifier says in the chart's own terms:

    chip("launch day", modifier().at(4, revenue[4]));       // over place 4, at that number's height
text("goal", modifier().at_value(8000));                // on the level of 8000
button("Details", modifier().at_place(11)) { open(); }; // over place 11, at the top

    (with no place said, it sits in the top left corner of the marks' area).

    AND ON THE CHART ITSELF

    .stacked() bars stand on top of each other instead of side by side .range(low, high) the numbers the y axis runs between (else: round numbers around the data) .enter(motion) how the marks appear (motion.sharp); a series can say its own .change(motion) how they get from old numbers to new ones .on_select { i -> } a place was clicked: i is its number, 0 the first .hover(state) keep a state at the place under the mouse (-1: none): anything on the screen can then follow what the chart is pointed at

    THE NUMBERS ARE PLAIN VALUES, not a state - like progress(fraction). When your state changes, build() runs again and makes a chart from the new numbers; the marks then glide from where they were to where they belong. One made with new numbers every second is a live chart.

    (Compose: Vico's CartesianChartHost with its layers. Android: MPAndroidChart's CombinedChart. HTML: Chart.js.)

    HOW IT WORKS

    A chart is ONE widget that paints everything itself; the things said in its block are not widgets but notes it keeps (chart.open is the chart whose block is running, as scope.open is for containers).

    Painting goes from numbers to pixels in three steps:

    1. THE SCALE. The lowest and highest number are found (with bars: 0
   is always in), and widened to round numbers so the y axis reads
   0, 50, 100 and not 0, 47, 94. `y_of` turns a number into a place.
2. EVERY MARK AT REST. Place i of n is a slot of the width; a bar
   fills its share of the slot, a point sits in the slot's middle
   (with no bars in the chart, the points run from edge to edge).
3. THE MOTION. Each mark is handed to the motion with how far along
   it is, and painted as the motion leaves it.

    MOVING. Nothing here is a timer. The chart knows WHEN things began (a series' born, the chart's change_at, in the host's clock) and works out from the time of each frame where everything is; while something is on its way it asks the host for another frame.

    WIDGETS IN A CHART. Every place a chart writes words - the labels of the axes, the legend, the marker's box, the marks themselves - can hold widgets instead (the block of its word), and widgets written straight into the chart's block are laid over the marks. Each is an ordinary CHILD of the chart: built with the chart (make_views), so the reconciler carries its memory across rebuilds like any other; measured in the chart's measure, which is how the chart knows the room a row of labels needs; and put in its place while PAINTING, where the places are worked out anyway - they move with every frame of a motion, and layout is not run for that. Only the marker's box is different: what it holds depends on where the mouse is, so it is built when the mouse comes to a place (tip_view).

    NEW NUMBERS. A rebuild makes a NEW chart object. The reconciler hands it the old one (adopt, below): the new chart takes over when each series appeared, and - if the numbers differ - notes where every mark stands on the screen at this moment as the place to glide from. So a change in the middle of a change starts from wherever the marks are.

    class chart_axis

    source

    chart_axis - the words along one side. Made with x_axis(...) or y_axis().

    class mark

    source

    mark - ONE drawn thing of a chart: one bar, or one point of a line.

    A motion is handed every mark at the place where it comes to rest, and changes it into what it looks like part of the way there. A drawing function (bars(...).draw_bar, line(...).draw_dot) is handed the mark as it is to be painted right now.

    class motion

    source

    motion - HOW the marks of a chart move: when the chart appears, and when its numbers change.

    chart { ... }.enter(motion.grow().stagger(0.04))            // bars rise one after another

chart { ... }.change(motion.glide().ease(EASE_SPRING))      // new numbers spring into place

    WHAT THERE IS

    motion.grow() up from the baseline motion.draw_on() from left to right: a line as if drawn by a pen, bars one by one motion.rise() lifted a little into place while fading in motion.fade() fading in where it stands motion.none() no movement: it is simply there motion.glide() for .change(...): from the old numbers to the new ones motion.custom { m: mark, t: decimal -> ... } your own

    AND WHAT EVERY ONE OF THEM TAKES

    .over(seconds) how long one mark takes .stagger(seconds) each mark starts this much later than the one before it .ease(curve) EASE_OUT, EASE_SPRING ... (above), or a function of your own

    YOUR OWN: the function gets a mark at the place where it comes to rest and t, how much of the way it has come (0 at the start, 1 when it has arrived - after the easing, so with EASE_OVERSHOOT it passes 1 on the way). Change the mark into what it looks like at that moment:

    motion.custom { m: mark, t: decimal ->
    m.grow(t);                      // up from the baseline ...
    m.opacity = t;                  // ... while fading in
}

    (They are functions of a class, not bare words, because fade already is a widget of this library and words like grow and none are likely to mean something in your own program.)
