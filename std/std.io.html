    Walks through a directory and everything below it, one entry at a time.

    Two ways to open: - replace (the default): the file starts empty; what was in it is gone at the first flush() or close(), even when nothing was written. - append: the content the file has when the writer is created is kept and the new text goes behind it.

    Every flush() writes the whole content again (old and new), which costs time proportional to the size of the file: flush when it matters, not after every line. Not thread safe.

    class path

    source

    Path arithmetic: taking paths apart and putting them together as text. Nothing here looks at the disk - the files do not have to exist - so the results depend only on the arguments (and, for the separator that is written, on the operating system).

    path.join("src", "main.sharp")          "src/main.sharp"
path.normalize("a/./b/../c//d/")        "a/c/d"
path.parent("/home/joe/a.txt")          "/home/joe"
path.file_name("/home/joe/a.txt")       "a.txt"
path.extension("archive.tar.gz")        "gz"
path.relative_to("/a/b/c", "/a/x")      "../b/c"

    Everything is static.

    Reading paths: both '/' and '\' separate the parts of a path, on every operating system, so a path written on one system can be taken apart on another. Writing paths: results use separator() - '/' on unix, '\' on windows - also for the separators that were in the arguments.

    Roots: a path is absolute when it starts with a separator ("/usr") or with a drive ("C:\dir"; also "C:dir", which windows reads as relative to the current directory of that drive - here its root is just "C:"). Server shares ("\\server\share") are not treated specially: the root is one separator.
