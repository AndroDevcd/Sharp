    std.guikit.layout.grids module

    grid

    class grid

    base widget : behavior · source

    grid - children in equal columns, filling row after row.

    grid(3) {                                  // always three columns
    for(i : _int64 = 0; i < count; i++) { photo_card(i); }
}.gap(12)
    grid_fit(160) { ... }.gap(12)              // as many columns as fit, each at least 160 wide

    Every column is the same width: the grid's width, less the gaps, split evenly. Children in the same row are made the same height (the tallest one's), so a row of cards lines up. The grid is as tall as its rows.

    .gap(n) room between the cells, both ways

    grid_fit is the one to reach for when the window can be resized: a wide window shows five cards across, a narrow one two, with no code of yours.

    HOW THE COLUMN COUNT IS FOUND for grid_fit (the rule Compose's GridCells.Adaptive uses): with gaps of g between cells of at least m, n cells need n*m + (n-1)*g, so the most that fit in width w is (w + g) / (m + g), rounded down - and never fewer than one.

    A grid inside a scroller scrolls like anything else. It lays out ALL its children; it is not yet a "lazy" grid that only builds what is visible. (Android: GridLayout / RecyclerView with a GridLayoutManager. Compose: LazyVerticalGrid. CSS: display: grid with repeat(auto-fill, minmax()).)
