    std.io.coroutines.sync module

    mutex semaphore

    class mutex

    source

    mutex - a lock for coroutines: one at a time, the others are SUSPENDED (not spinning, not blocking their thread) until it is their turn.

    USAGE guard := new mutex();

    guard.with_lock({ ->            // acquire, run the block, release - whatever happens
    balance.value = balance.value + 10;
});
    guard.acquire();                // or by hand, when the two ends are in different places
try { ... } finally { guard.release(); }

    WHEN TO USE IT INSTEAD OF lock(obj) { } lock(obj) is for a few instructions. A fiber that sleeps (delay, channel, join ...) while it holds lock(obj) keeps everybody else out, and an exception that leaves a lock block does not release it. A mutex may be held across suspension points, waiting for it can be cancelled, and it is handed over in the order the waiters arrived.

    It is NOT reentrant: a coroutine that calls acquire() while it holds the mutex waits for itself for ever (try_acquire() returns false). It works from plain fibers and threads as well.

    Kotlin equivalent: kotlinx.coroutines.sync.Mutex (acquire = lock, release = unlock, with_lock = withLock; lock is a keyword in Sharp). C++ equivalent: std::mutex whose lock() suspends a fiber.

    LOCKING DISCIPLINE lk (a stripe of lock_stripes, picked once) guards held, owner and waiters, and is the guard of every waiter queued here. No other lock is taken while it is held, nothing throws and no user code runs inside a lock block. release() with waiters does not unlock: it hands the mutex straight to the oldest waiter (held stays 1, owner becomes that fiber), so nobody can jump the queue.

    Suspends: acquire(), with_lock(). Cancellation: acquire() is a cancellation point; a cancelled wait does not get the mutex.

    mutex()

    an unlocked mutex

    def acquire()

    Take the mutex, waiting for it if somebody else has it.

    SUSPENDS while it is taken. A cancellation point: checked on entry; when the caller is cancelled while it waits it is taken out of the queue and cancellation_exception is thrown (the mutex is then NOT held). Kotlin: Mutex.lock()

    def holds_lock() : bool

    true when the calling fiber is the one that holds the mutex. Kotlin: Mutex.holdsLock(owner)

    def is_locked() : bool

    true while somebody holds the mutex. Kotlin: Mutex.isLocked

    def release()

    Give the mutex back; the coroutine that has waited longest gets it. Never suspends. Any fiber may release (hand-over patterns are allowed), holds_lock() tells who holds it. @throws illegal_state_exception when the mutex is not held Kotlin: Mutex.unlock()

    def try_acquire() : bool

    Take the mutex if it is free right now. @return true when the caller holds it now Never suspends, not a cancellation point. Kotlin: Mutex.tryLock()

    def waiting_count() : decimal

    number of coroutines waiting for the mutex right now

    def with_lock(block: ()())

    acquire(), run block, release() - also when the block throws (the exception is thrown on after the release).

    The block runs in-line and may capture locals. SUSPENDS while it waits for the mutex; a cancellation point (a cancelled wait does not run the block). @throws illegal_state_exception when called from inside the block of another with_lock() on the same fiber, of this or any other mutex (THE NESTING RULE, std/io/coroutines/scope/scopes.sharp: the runtime cannot continue a fiber with one function on its stack twice). Take the second mutex with acquire() / release() instead. Kotlin: mutex.withLock { }

    class semaphore

    source

    semaphore - a counter of permits: at most N coroutines inside at the same time, the others are suspended until a permit comes back.

    USAGE downloads := new semaphore(4); // at most 4 at once

    for(i : decimal = 0; i < 100; i++) {
    launch(downloads, { s: object ->
        limit := s as semaphore;
        limit.acquire();
        try { fetch_next(); } finally { limit.release(); }
    });
}
    downloads.with_permit({ -> fetch_next(); });     // the same, for an in-line block

    A semaphore with 0 permits is a signal: one side waits in acquire(), the other wakes it with release(). It works from plain fibers and threads as well.

    Kotlin equivalent: kotlinx.coroutines.sync.Semaphore (with_permit = withPermit). Java equivalent: java.util.concurrent.Semaphore (fair). C++ equivalent: std::counting_semaphore whose acquire() suspends a fiber.

    LOCKING DISCIPLINE lk (a stripe of lock_stripes, picked once) guards permits and waiters, and is the guard of every waiter queued here. No other lock is taken while it is held, nothing throws and no user code runs inside a lock block. release() with waiters hands the permit straight to the oldest waiter instead of increasing the count (first come first served).

    Suspends: acquire(), with_permit(). Cancellation: acquire() is a cancellation point; a cancelled wait does not take a permit.

    Take one permit, waiting for one if there is none.

    def acquire_for(ms: decimal) : bool

    acquire() that gives up after ms milliseconds. @return true when a permit was taken, false when the time ran out SUSPENDS for at most ms. A cancellation point. Java: tryAcquire(timeout, MILLISECONDS)
