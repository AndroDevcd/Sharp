    class lock_stripes

    source

    lock_stripes - a small, fixed set of lock objects shared by all the short lived synchronisation objects of the library (jobs, deferreds, futures, ...).

    USAGE class job { private lk : object = lock_stripes.next(); // picked once, never changes def is_active() : bool { lock(lk) { return state == 1; } } }

    WHY NOT lock(self) The runtime keeps one entry for every object that was ever used in a lock() statement, in ONE linked list, and every lock and unlock walks that list to find its entry. A program that starts 10,000 coroutines and locks each job once would make that list 10,000 long and every lock in the whole program 10,000 steps slow. With stripes the list stays at STRIPE_COUNT entries however many jobs exist. Objects that share a stripe only share the lock, not their data; the critical sections are a few field reads and writes, so the extra contention is small.

    C++ / Java equivalent: lock striping, e.g. the segments of the old java.util.concurrent.ConcurrentHashMap or Guava's Striped<Lock>.

    THE RULE THAT COMES WITH IT Never take a second library lock while holding a stripe. Two different objects may have been given the SAME stripe, and the runtime lock is not counted: lock(a) { lock(a) { } ...here the lock is already released... }. A nested lock on the same stripe would silently end the outer critical section early. Every class that uses a stripe states in its own comment that it follows this rule.

    LOCKING DISCIPLINE stripes is filled once by setup(), which the start-up code runs on the main thread before any other thread or fiber exists (std.io.coroutines start_scheduler(), called by platform.srt_init), and is only read afterwards. cursor is advanced without a lock on purpose: two fibers that race only get the same stripe, which is harmless.

    Nothing here suspends.

    Functions

    static def next() : object

    The lock object for a new synchronisation object: the stripes are handed out in turn. Keep the result in a field; do not call next() per lock.

    static def setup()

    Create the lock objects. Safe to call more than once. Must run for the first time while the program still has a single fiber (see above).

    class wait_queue

    source

    wait_queue - the fibers waiting for one resource, first come first served.

    USAGE waiters := new wait_queue(); // a field of the resource

    lock(lk) { waiters.add(w); }          // the fiber that has to wait
w.park();
    lock(lk) {                            // the fiber that frees the resource
    w := waiters.pop_waiting(waiter.RESUMED);
}
if(w != null) w.unpark();

    It is a doubly linked list threaded through the waiters themselves (waiter.next / prev / queue), so add, pop and remove are O(1) and nothing is allocated. C++ equivalent: an intrusive std::list<waiter*>. Java equivalent: the CLH queue inside AbstractQueuedSynchronizer, without the lock-free part.

    LOCKING DISCIPLINE A wait_queue has NO lock of its own. Every method must be called while holding the lock of the resource that owns the queue, and that must be the same lock the queued waiters were created with (waiter.guard), because pop_waiting() claims waiters and a claim is only legal under their guard.

    Nothing in this class suspends, and nothing is a cancellation point.

    Empty the queue without claiming anybody.

    true when no waiter is queued

    def peek() : waiter?

    the waiter that would be popped next, or null. It stays in the queue.

    def pop() : waiter?

    Take the oldest waiter out of the queue whatever its state is. Null when the queue is empty.

    def pop_waiting(new_state: decimal) : waiter?

    Take the oldest waiter that is still waiting out of the queue and claim it with waiter.resume(new_state). Waiters that were claimed before (timed out or cancelled and not removed yet) are dropped on the way.

    @return the claimed waiter - the caller MUST call unpark() on it after releasing the lock - or null when nobody is waiting.

    def pop_waiting_with(new_state: decimal, value: object?) : waiter?

    def remove(w: waiter)

    Take w out of the queue if it is in THIS queue; does nothing otherwise (it was popped already, or never added). This is what a fiber calls after its wait ended with CANCELLED or TIMED_OUT.

    def size() : decimal

    number of waiters in the queue (claimed ones that were not removed yet included)

    class waiter

    source

    waiter - one fiber waiting for one event. The parking primitive every blocking operation in the coroutine and concurrency library is built on (job.join, channel.send/receive, mutex, semaphore, future, latch, ...).

    USAGE (this is the whole pattern, self is the resource that is waited for):

    // the fiber that has to wait
w := new waiter(lk);                 // lk = the lock that guards the resource
lock(lk) {
    if(resource_is_ready) { ...take it...; return; }
    waiters.add(w);                  // a wait_queue, guarded by lk as well
}
w.park();                            // sleeps, costs no cpu
// w.state says why it woke up: RESUMED, CANCELLED, TIMED_OUT, CLOSED
    // the fiber that makes the resource ready
woken : waiter? = null;
lock(lk) {
    w := waiters.pop();
    if(w != null && w.resume(waiter.RESUMED) != 0) { woken = w; }
}
if(woken != null) woken.unpark();    // outside the lock

    C++ equivalent: one std::condition_variable wait with its predicate, or a Linux futex wait/wake pair. Kotlin equivalent: a CancellableContinuation. Java equivalent: LockSupport.park / unpark plus the "permit" that makes an unpark before the park not get lost.

    WHY THIS IS NOT JUST fiber.suspend() / fiber.unsuspend() The runtime gives us two calls and neither remembers anything: suspend(self) the fiber sleeps until somebody unsuspends it unsuspend(f) wakes f if it is suspended, does NOTHING if it is running So "check the condition, then suspend" loses the wake-up when the other fiber unsuspends between the check and the suspend: the fiber then sleeps forever. A waiter closes that hole with three rules:

    1. CLAIM. state goes from WAITING to something else exactly once, under guard, and wake is set to 1 in the same step. Whoever makes that change has "claimed" the waiter. (resume / abandon / the timeout in park_for)

    2. CHECK AND SLEEP IN ONE STEP. The waiting fiber reads wake and makes the suspend call in a sequence of instructions that contains no jump, no call and no allocation (see suspend_unless_woken). The interpreter and the JIT only switch fibers at jumps, calls, returns, int and object creation, so no other fiber can run on this thread between the read and the suspend: when wake was 0 the fiber really is suspended next, when it was 1 the suspend call is turned into a no-op (it is given fiber id -1).

    3. HANDSHAKE. Another THREAD can still see the fiber as "running" for the few instructions between the read and the suspend, and unsuspend reports that (result 1). unpark() therefore repeats the call until it either hit a suspended fiber or the waiter says it noticed wake by itself (done). And the waiting fiber does not leave park() before the other side has finished (unparked), so a late unsuspend can never hit some later, unrelated sleep of the same fiber (it would cut a delay() short).

    The retry in rule 3 yields the OS thread between attempts. It only runs while the other thread is inside those few instructions, so in practice it goes around zero or one time. This is the one place in the library that waits by retrying; a runtime call "suspend unless a wake-up is pending" would remove it (see the final report of the library redesign).

    LOCKING DISCIPLINE guarded by guard (the lock of the resource this waiter waits for): state, item, tag, next, prev, queue written under guard, read without it by the owner fiber: wake (only ever goes 0 -> 1), self_claimed (only written by the owner) not locked, each written by one side only, each only goes 0 -> 1: done written by the owner fiber unparked written by the fiber that called unpark() never changes after the constructor: fib, guard

    A waiter is used for ONE wait and then dropped. Never reuse one.

    Can suspend: park() and park_for(). Nothing else blocks. Cancellation: a waiter knows nothing about jobs. The coroutine library wakes a waiter of a cancelled job with resume(waiter.CANCELLED) (see std.io.coroutines await_waiter()).

    Functions

    waiter(guard: object)

    A waiter for the fiber that is running right now.

    @param guard the lock that protects the resource (and with it this waiter's state). resume() and abandon() must be called while holding it.

    def abandon(new_state: decimal) : bool

    Claim the waiter for its OWN fiber: "I do not want to wait any more" (the job was already cancelled, a timeout passed). MUST be called by the owner fiber while holding guard. Does not block.

    @return true when the waiter is now withdrawn (park() will return at once, nobody will unpark it). false when another fiber claimed it first: the owner must still call park() to finish the handshake and then act on state.

    def is_waiting() : bool

    true while nobody has claimed the waiter. Hold guard for an answer that stays true.

    static def now_millis() : decimal

    wall clock in milliseconds, as a native number

    def park()

    Sleep until the waiter is claimed. Call it exactly once, from the owner fiber, WITHOUT holding guard (or any other lock: a fiber that sleeps while it holds a lock blocks everybody who wants that lock).

    Returns at once when the waiter was claimed already. On return state is never WAITING.

    SUSPENDS the calling fiber. The thread is free to run other fibers. Not a cancellation point by itself (see the class comment).

    def park_for(ms: decimal)

    park() that gives up after ms milliseconds: the waiter then claims itself with state TIMED_OUT. Same rules as park().

    After a time out the waiter may still be linked in a wait_queue: the caller removes it (wait_queue.remove, under guard). A waker that pops it before that simply gets 0 from resume() and moves on.

    Takes guard for a moment when the time runs out, so do not hold it.

    @param ms how long to wait at most. 0 or less: do not sleep at all, time out at once unless the waiter was claimed already.

    def resume(new_state: decimal) : bool

    Claim the waiter for another fiber: the event it waits for has happened. MUST be called while holding guard. Does not block.

    @param new_state RESUMED, CANCELLED or CLOSED @return true when this call claimed the waiter: the caller MUST then call unpark() (once, soon, preferably after releasing the lock). false when the waiter was claimed before (it timed out, was cancelled or resumed by somebody else): the caller must look for another waiter and must NOT call unpark().

    def resume_with(new_state: decimal, value: object?) : bool

    resume() that also hands a value to the waiting fiber (it reads item after park() returns). Same rules as resume().

    static def sleep_raw(ms: decimal)

    Sleep ms milliseconds with the plain runtime timer: no waiter, no cancellation, cannot be woken early. For the insides of the library only; user code calls delay().

    def unpark()

    Wake the owner fiber. Call it exactly once after resume() / resume_with() returned 1, from the fiber that made that call. Do NOT hold guard longer than needed around it (it is legal to hold it, the owner needs no lock to wake up, but other fibers wait for the lock meanwhile).

    Does not block. May retry for a moment while the owner fiber is between "decided to sleep" and "asleep" on another thread (see rule 3 above).

    static def yield_fiber()

    give the other fibers of this thread a turn; no cancellation check (the raw delay(0))

    static def yield_os_thread()

    let the operating system run another thread for a moment (std::this_thread::yield)
