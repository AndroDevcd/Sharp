    class camera

    source

    camera - the eye a scene is seen through. Inside a scene:

    camera().at(0, 2, 6).look_at(0, 1, 0);          // stands here, looks there
camera().at(x, y, z).facing(heading, tilt);     // stands here, looks this way
camera().orbit();                               // drag to look round the scene, wheel to zoom
camera().walk(land);                            // a person walking over the land

    A scene that says nothing about its camera gets one that stands back far enough to see everything in it.

    DIRECTIONS: a heading is degrees round the up axis - 0 looks along -z, 90 along +x, like a compass seen from above. The tilt is degrees DOWN (below 0: up).

    THE THREE THAT MOVE BY THEMSELVES

    orbit()     the mouse dragged turns the eye round a point - the middle of the scene, or
            the point given - and the wheel moves it closer or away. For looking AT
            something: a model, a product, a board.
walk()      W A S D or the arrow keys walk (left and right arrows turn), dragging the
            mouse looks round. With walk(land) the eye stays a person's height above
            the land. For being IN a world.
fly()       like walk, but forward is wherever the eye looks - up included.

    Each keeps where it has got to when the screen is rebuilt.

    (three.js: PerspectiveCamera + OrbitControls / PointerLockControls. Godot: Camera3D.)

    class endless

    base thing · source

    endless - land with no edge. It is made piece by piece round the eye as the eye travels, and the pieces left far behind are let go: however far you go there is land ahead, and the machine holds only what is near.

    hills := endless(128, 64, { x: decimal, z: decimal -> return rolling(x, z); });
hills.colored({ height: decimal, steep: decimal -> return steep > 0.6 ? 0x6D675FFF : 0x5E7740FF; });
around := state(0);
    // in build():
hills.ready_round(eye_x, eye_z);                    // the first pieces, all at once
scene {
    for(i : _int64 = 0; i < hills.shown(); i++) {
        add(hills.piece(i));                        // the pieces round the eye
    }
    eye := camera().walk(hills);                    // the eye stays above it, wherever it goes
    on_frame { f: frame ->
        if(hills.follow(eye.x, eye.z)) { around.value = around.value + 1; }    // new land: build again
    };
}

    Your function is the land: it must answer for ANY x and z (noise does), and the same answer every time. Each piece is tile metres along its edge, cut into cells squares; piece (0, 0) has its corner at (0, 0), piece (1, 0) lies next to it towards +x, piece (-1, 0) on the other side.

    follow(x, z) is asked every frame. It works on the next missing piece for a moment only - a few rows of heights - so that the picture never stops while land is made, and answers true when the pieces to show have changed.

    What stands on the land is yours to put there, piece by piece:

    for(i : _int64 = 0; i < hills.shown(); i++) {
    p := hills.piece(i);
    scatter(pine, 300).on(hills).within(p.x, p.z, p.x + hills.tile, p.z + hills.tile)
            .seed(hills.number_of(p));              // every piece its own forest
}

    (height_at and steep_at ask your function itself, so they answer anywhere, whether that land has been made or not.)

    (Godot, Unity: "chunks", "terrain streaming".)

    class flock

    base thing · source

    flock - many copies of one thing that move together, round the place the flock stands at: a school of fish, a flight of birds, gnats over a pond.

    school := flock(fish, 300).at(80, 12, 90).spread(9).speed(3);

    Each goes round the middle at its own distance, nose first, the inner ones quicker, rising and sinking a little as it goes. The flock itself is a thing: move it, bob it, send it round a circle (circling) and all of them go along. The copies cost what a scatter's do - one shape on the card.

    (Give it a thing whose nose points along -z, as a thing's "forward" is.)

    class mesh

    source

    mesh - a shape you make yourself: corners in space and triangles between them.

    wall := new mesh();
a := wall.corner(0, 0, 0);
b := wall.corner(4, 0, 0);
c := wall.corner(4, 3, 0);
d := wall.corner(0, 3, 0);
wall.quad(a, b, c, d);
wall.texture("assets/brick.png");
    scene { add(wall); };

    EVERYTHING 3D IS A MESH underneath: cube, sphere, terrain and tree build one with exactly the functions below, and a model file is read into several. So whatever they can show, a mesh of your own can.

    A CORNER has a place, and may have three more things:

    a facing            which way the surface looks there (nx, ny, nz). Light is worked
                    out from it. Leave it out and smooth() works one out for you
a texture point     where of the texture is at this corner: (0, 0) its top left,
                    (1, 1) its bottom right; beyond 1 the texture repeats
a colour            multiplied into the surface there (tint): shade a model by hand,
                    or colour land by its height, without any texture

    A TRIANGLE names three corners COUNTER-CLOCKWISE as seen from the side that shows. Its back is not drawn (a closed shape never shows a back) - unless the mesh is two_sided().

    THE SPACE: x to the right, y UP, z towards you; a unit is a metre.

    WHAT IT IS MADE OF, for the whole mesh: color, texture, shiny, glow, and two_sided / cut_out / see_through / unlit.

    A MESH THAT CHANGES (water, a trail, a morphing shape): change the lists - points, normals, uvs, tints - or clear() and build again, then say changed(). It is sent to the graphics card again before the next frame.

    A shape of several materials is several meshes: body.also(glass).

    (three.js: BufferGeometry + Material. Godot: ArrayMesh / SurfaceTool.)

    Fields

    pointsdecimal[]x y z for every corner
    normalsdecimal[]its facing: nx ny nz
    uvsdecimal[]its texture point: u v
    tints_int64[]its colour, 0xRRGGBBAA
    faces_int32[]three corner numbers for every triangle
    corner_count_int64
    face_count_int64
    paint_int64
    picture_int64its texture's id (0: none)
    shinedecimal
    lightdecimal
    both_sidesbooltwo_sided()
    holesboolcut_out()
    blendedboolsee_through()
    plainboolunlit()

    def corner(x: decimal, y: decimal, z: decimal, nx: decimal, ny: decimal, nz: decimal) : _int64

    def corner(x: decimal, y: decimal, z: decimal, nx: decimal, ny: decimal, nz: decimal, u: decimal, v: decimal) : _int64

    def cut_out() : mesh

    the see-through pixels of its texture are holes: leaves, a fence, a grate. (Also seen from both sides.)

    def faceted() : mesh

    give every triangle corners of its own, all facing the way the triangle does: the surface then shows its facets - the cut-gem, "low-poly" look.

    def glow(amount: decimal) : mesh

    def moved(dx: decimal, dy: decimal, dz: decimal) : mesh

    a four-cornered face (two triangles), counter-clockwise as seen from the side that shows

    def ready() : _int64

    the model this mesh is on the graphics card: sent the first time it is asked for, and again after it changed. (The framework asks; a program needs this only to hand the model to something that takes model ids.)

    def see_through() : mesh

    see-through, mixed with what is behind it: glass, water, smoke

    def send(into: _int64)

    def shiny(amount: decimal) : mesh

    how strongly it shows the sun's glint: 0 chalk .. 1 polished

    def smooth() : mesh

    work out every corner's facing from the triangles that meet at it: the surface then looks rounded. Corners made without a facing get this by themselves; call it yourself after moving corners by hand.

    def stretched(sx: decimal, sy: decimal, sz: decimal) : mesh

    stretch along each axis (1: unchanged). Facings are worked out again by smooth() when the stretch is uneven.

    def texture(path: string) : mesh

    def triangle(a: _int64, b: _int64, c: _int64)

    a triangle between three corners, counter-clockwise as seen from the side that shows

    def turned(yaw: decimal, pitch: decimal, roll: decimal) : mesh

    turn round (0, 0, 0), in degrees, as a thing is turned: heading, then nose up, then rolled

    def two_sided() : mesh

    seen from the back too (a leaf, a flag, a sheet of paper)

    def unlit() : mesh

    its own colour whatever the light

    class plant

    base thing · source

    plant - a tree, grown by the program: a trunk that tapers and leans, limbs that branch and reach up, and foliage on them.

    oak := tree(7);                 // a broad-leaved tree; another number, another tree
fir := pine(3);                 // a conifer
    scene {
    add(oak).at(4, 0, 0 - 2);
    scatter(fir, 2000).on(land).between(2, 60);        // a forest of it
}

    HOW A TREE IS MADE (the way games make them): the WOOD is real shape - tubes of bark, thinner with every branching. The LEAVES are not: no machine draws a hundred thousand leaves. Each spray of leaves is one flat card with a picture of leaves on it, see-through between them; a few dozen cards, facing all ways and lit as if they were the outside of one round crown, read as a tree. A whole tree is about a thousand triangles.

    It needs no picture files: the bark and the leaves are textures the library draws itself. Your own go on with

    tree(7).bark("assets/oak_bark.jpg").leaves("assets/oak_leaves.png");

    (a leaf picture: a spray of leaves on a see-through background, spreading from the middle; for a pine: a twig with its base at the bottom edge).

    The same number always grows the same tree, and every tree(7) shares one shape on the graphics card: a forest costs a tree.

    FAR AWAY a tree is drawn from a much simpler shape (simple: about seventy triangles); scatter(...) switches to it by itself.

    Fields

    woodmeshtrunk and limbs
    foliagemeshthe leaf cards
    simpleplant?the same tree with far fewer triangles, for far away

    class scattering

    base thing · source

    scattering - many copies of one thing, strewn about: a forest, rocks on a slope, grass, a crowd of crates.

    pine := tree(7);
scene {
    add(land);
    scatter(pine, 3000).on(land).between(1, 40);       // where the land is 1 to 40 metres high
    scatter(rock, 200).within(0, 0, 100, 100);         // or just over an area
}

    However many there are, the scene hands them to the graphics card as ONE thing, and only the copies in view are drawn. Each copy stands at a place of its own, turned its own way and at its own size - always the same ones for the same seed, so a forest does not move when the screen is rebuilt.

    on(land)                on this land, each copy at the land's height
between(low, high)      only where the land is between these heights
slopes(most)            only where it is no steeper than this (trees do not stand on cliffs)
steeper(least)          only where it is at least this steep (rocks on a cliff's face, moss on a bank)
within(x0, z0, x1, z1)  only inside this area (else: the whole land)
clear_of(x, z, radius)  none within this far of a point: a clearing, a path, where the player starts
sizes(smallest, largest)    each copy's size, picked between these (1: the thing's own)
seed(n)                 another arrangement
far(cheaper, 80)        beyond 80 metres draw this simpler thing in its place

    On endless land say within(...) too: it has no edges to stand in for it.

    class scene

    base widget : behavior, pointer_target, wheel_target, stateful · source

    scene - a 3D view: a widget like any other, with a world in it.

    scene {
    cube(1).texture("assets/crate.png").spin(40);
}
    scene(modifier().grow(1).fill_height()) {
    camera().orbit();
    sun().from(0.8, 0.5, 0.3).shadows();
    ground(20).texture("assets/concrete.png", 8);
    model("assets/car.obj").color(paint.value);
}

    IT WORKS LIKE A COLUMN DOES: the block runs, and what it makes belongs to the scene - things (cube, sphere, model, group ...) in the order the lines run, with ordinary if and for deciding what is there. When a state the block read changes, the screen is built again and the scene shows the new world. Its box (size, place in the layout) comes from the modifier, like every widget's.

    WHAT A SCENE HAS BESIDES THINGS

    camera()    the eye (camera.sharp)                 - else: far enough back to see everything
sun()       the light (lights.sharp)               - else: a high sun, no shadows
lamp()      lights at a place
sky(top, horizon)       the colours of the sky     - else: a clear day
backdrop(colour)        one flat colour instead of a sky
fog(colour, from, to)   far things fade into it
on_frame { f -> ... }   your code, run before every frame: move things, read the keys

    AND ANY WIDGET WRITTEN IN THE BLOCK IS LAID OVER THE VIEW - a score, a health bar, buttons - like in every container of this library:

    scene {
    cube(1).spin(40);
    text("Score: " + score.value, modifier().padding(16)).size(24);

    class sun

    sun - the one light that reaches everywhere in a scene, from one direction.

    class terrain

    base thing · source

    terrain - land: ground whose height you give as a function of where it is.

    land := terrain(320, { x: decimal, z: decimal -> return hills(x, z); });
land.texture("assets/grass.png", 60);
    scene {
    add(land);
    camera().walk(land);                        // the eye stays above it
    model("assets/cabin.obj").at(160, land.height_at(160, 150), 150);
}

    The land is a square of size metres with one corner at (0, 0, 0), running towards +x and +z. It is made ONCE, when terrain(...) is called - keep it in a variable outside the screen's build, and add(...) it in the scene: making land asks your function for a height at every corner of its grid (129 x 129 of them unless you say how finely to cut it).

    height_at(x, z) answers from the grid, quickly, so it can be asked every frame for a character's feet. (Outside the land it answers the nearest edge.)

    colored(...) paints the land by what it is - height and steepness - with no texture at all, or together with one:

    land.colored({ height: decimal, steep: decimal ->
    if(steep > 0.6) { return 0x6D675FFF; }      // rock
    if(height > 40) { return 0xE4E8ECFF; }      // snow
    return 0x5E7740FF;                          // grass
});

    class thing

    source

    thing - anything that stands in a scene: a shape, a model from a file, a group of other things.

    You rarely write thing itself. The words make them - cube, sphere, model, group, terrain, tree ... - and everything about how a thing sits and looks is chained onto it, the way a text's size is chained onto a text:

    model("assets/car.obj").at(0, 0, -4).turn(30).color(0xD63031FF);

    WHERE IT IS at(x, y, z) its place: x to the right, y UP, z towards you; a unit is a metre turn(heading) degrees round the up axis: 0 faces along -z, 90 along +x turn(heading, pitch, roll) ... then nose up, then rolled scale(s) 1: its own size A thing inside a group is placed, turned and scaled RELATIVE to the group.

    HOW IT LOOKS color(0xRRGGBBAA) its colour (a texture is tinted by it; an alpha below FF makes it see-through) texture(path) a picture over it; texture(path, 40): laid 40 times across shiny(0 .. 1) how strongly it glints glow(0 .. 1) how much of its colour it gives off by itself

    MOVING BY ITSELF (worked out on the graphics side: costs the program nothing) spin(40) degrees a second round the up axis bob(0.2, 2) up and down, this far, this fast

    CLICKS use the names a view's modifier uses: click { ... } double_click { ... } right_click { ... }

    A thing you keep in a variable can be changed at any time - in on_frame, from a button, from a timer - and the scene shows it:

    ship.turn_by(90 * f.step);
ship.forward(12 * f.step);

    class water

    source

    water - the water a scene is in, when the eye is under its surface. Made with underwater(shallow, deep) inside a scene; every setting has a value already, so underwater(...) alone is a sea.

    scene {

    WHAT IT DOES TO THE PICTURE

    colour      a thing loses its own colour with distance and takes the
            water's: bright towards the surface, `deep` looking down
the surface seen from below, rippling, brightest straight overhead
caustics    the surface's ripples focus the sun into bright lines that
            wander over everything the sun reaches, fainter with depth
shafts      beams of light from the surface down the sun's slant

    The same water serves a lake, a flooded cave or a pool: the colours and the sight decide which. (Godot: an Environment with volumetric fog and a water shader. three.js: FogExp2 and a hand-written caustics pass.)
