    class compress_exception

    base exception · source

    DEFLATE: the compression inside gzip, zip, png and https

    small := deflate.compress(bytes);
same := deflate.decompress(small);

    This is the bare compressed stream. Files and the network wrap it: gzip (gzip.sharp) adds a header and a checksum, zlib a shorter one, a zip archive (zip.sharp) keeps many files, each deflated. Use those unless a format asks for the bare stream.

    HOW IT WORKS, in two steps:

    1. Repeats are replaced by "the same as <length> bytes, <distance> bytes back" (LZ77): abcabcabc is abc and then "6 bytes from 3 back". A repeat can reach 32768 bytes back and be 3 to 258 bytes long. 2. What is left - plain bytes, lengths and distances - is written in codes of different lengths, the frequent ones short (Huffman codes).

    decompress() reads every stream the format allows (stored, fixed and dynamic codes). compress() finds repeats with a table of where each three bytes were last seen and writes the format's FIXED codes: a little larger than what zlib makes (it builds codes for each block), read by everything.

    Written in Sharp: nothing to install on any system. Megabytes take a moment; for a great deal of data call the system's zlib through extern.

    Throws compress_exception when data to decompress is damaged or cut off.

    Java comparison: java.util.zip.Inflater / Deflater (with nowrap); Python: zlib with wbits=-15.

    class gzip

    source

    GZIP: compressed data as files and web servers carry it

    small := gzip.compress(bytes);                      // what `gzip file` writes: the content of a .gz file
same := gzip.decompress(small);
    gzip.compress_text("a long text ...")               // from and to texts
gzip.decompress_text(bytes)
gzip.compress_file(new file("log.txt"), new file("log.txt.gz"));
gzip.decompress_file(new file("log.txt.gz"), new file("log.txt"));
gzip.is_gzip(bytes)                                 // does it start as gzip data does?

    Gzip is deflate (deflate.sharp) with a short header in front and, behind it, a checksum and the length of the original - so damaged data is NOTICED: decompress throws compress_exception when the checksum or the length does not fit, where bare deflate would hand back wrong bytes.

    zlib is the same idea with a smaller wrapper (2 bytes in front, another checksum behind); it is what png images and many protocols use:

    zlib.compress(bytes)        zlib.decompress(bytes)
    Java comparison: GZIPOutputStream / GZIPInputStream; Python: gzip.compress / gzip.decompress.

    class zip_entry

    source

    ZIP ARCHIVES: many files in one, each compressed

    // read one
archive := zip_archive.open(new file("release.zip"));
archive.names()                             // "readme.txt", "bin/app", "docs/" ...
text := archive.read_text("readme.txt");
data := archive.read("bin/app");            // bytes
archive.extract_all("unpacked");            // every file, into that folder
    // make one
made := new zip_builder();
made.add("readme.txt", "some text");
made.add_bytes("data/numbers.bin", bytes);
made.add_file("bin/app", new file("build/app"));
made.save(new file("release.zip"));

    Names in an archive use / whatever the system, and a name that ends in / is a folder. Every file's checksum is checked when it is read: a damaged archive is a compress_exception, not wrong bytes.

    extract_all refuses a name that would land outside the folder it is given ("../../etc/passwd"): an archive from somewhere else cannot write where it pleases.

    An archive is read into memory whole and built there: fine for the megabytes archives usually are, not for gigabytes. Not read: archives with passwords, the "zip64" form for files over 4 GB, and compression other than deflate (which is what every zip tool writes by default).

    Java comparison: java.util.zip.ZipFile and ZipOutputStream; Python: zipfile.ZipFile.
